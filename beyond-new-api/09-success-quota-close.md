# 09 成功证据关闭执行配额

2026-11-18。状态：已实现并完成关键定向回归，完整门禁与最终验收尚未完成，不单独增加S6容量轮次。落实03 §2.4、§3.4及SR-15，不改变金额算法、签名事实、吊销线性化、持久队列和外部ACK契约。

## 1. 依据与目标

S5的60RPS次轮每3750个含预热请求仍有3750次core_quota_close_v1、11250次core_preflight_v1、7500次core_quota_v1。成功路径先接纳终态证据，再单独CLOSE事务、读取preflight、释放Redis、逐租约回写PG；CLOSE顶层累计4694ms。不能把嵌套SQL重复相加或将这些elapsed直接当CPU收益。

目标是由已验证的成功证据在原PG组事务内关闭执行，成功Gateway不再发送CLOSE。失败、取消、未发送、BEGIN不明、证据接纳失败仍沿原CLOSE/abort路径。此片不删除旧CLOSE接口，因为它仍有真实消费者和历史用途。

## 2. 权威条件与事务

追加函数迁移，不修改已发布SQL checksum。core_evidence_group_v1保留全部预锁、当前安全吊销、owner、revision、冲突、金额及组隔离逻辑。只有原逻辑已接受并选定的request处于SUCCEEDED、billing_outcome=SUCCESS，selected_attempt的state也为SUCCEEDED时才自动关闭；不因caller带一个request_state、只存在RAW、重复/隔离事件或UNKNOWN permit就释放。完成执行与金额最终可计量是不同判定：真实成功terminal即使尚缺最终计量也可关闭执行配额，但未知资金责任继续保留，不把租约释放当成资金退款。

在组内全部事实处理之后、资金收尾之前，仅对已持有FOR UPDATE的request检查上述状态，并要求存在该selected attempt的合法ACCEPTED receipt，且其attempt_state/request_state同时为SUCCEEDED。用UPDATE RETURNING的关闭集合把尚在ADOPTION_PENDING/ACTIVE的租约置RELEASE_PENDING。此锚点同时支持旧成功事实重投补齐，不把任意duplicate/raw当授权。保持原CLOSE对request所有租约的关闭范围，不凭本片重定义历史重试的并发语义。BEGIN/next仍核execution_closed_at；并发renew/释放只沿原permit与租约行锁，不增加反向账户锁。

后续任意供应或客户结算、约束检查失败必须连同关闭和租约转换整体回滚。隔离、未授权及不成功事件不得自行构造执行关闭。旧CLOSE可幂等重放；旧版Gateway多发CLOSE无损，历史成功事件的合法重投可补齐关闭。新Gateway须与带新迁移的worker部署，本片不宣称已支持任意混合版本滚动发布。

## 3. Gateway与恢复所有权

Gateway只有bridge.finish成功耐久返回且选定attempt_state/request_state均SUCCEEDED时省略CLOSE。finish失败、接纳未知或任何其他终态仍由finally尝试原CLOSE，不在错误时假定worker已有事实。停止续租、释放本地发送许可、插件dispose及健康观测保持顺序和有界收尾。

省略CLOSE后，在worker处理前Redis并发租约仍占用；PG提交后由现execution_quota_recovery_v1释放Redis并记RELEASED。Core或worker崩溃重启后根据PG RELEASE_PENDING继续，重复释放不得重复扣RPM/TPM或恢复已释放租约。证据排队时占用延长，必须证明不会提前超发；不通过直接删除Redis key换取吞吐。耐久入队不等于PG接受；安全吊销、冲突或既有终态不一致可能使该证据不能关闭执行。省略CLOSE前必须处理这些租约的技术恢复边界，不能声称所有成功HTTP都会自动释放。§5技术过期已实现，Gateway按本节条件省略成功CLOSE，异常路径仍保留。

现worker循环仅按过期RESERVED候选是否满批继续，默认每5秒只释放32个租约，不足以承接成功路径。改为本轮释放满批或过期候选满批均继续；成功证据提交通过一个有界wake位唤醒单一恢复循环，短批且无新唤醒时才等待配置间隔，失败仍等待间隔。每次工作量维持原batch上限，不引入并发恢复队列或忙等。连续满批会多轮推进；无处理进展不自旋。测试、成品与容量的真实worker必须配置原生产Core恢复身份，不能继续使用无恢复客户端的开发装置。

恢复响应明确为released/pending/failed，均为0–100整数且released+failed=pending；selected但全部失败不再与无工作混淆。worker只把匹配attempt的COMMITTED/ABORTED回执计入abort进展。部分Redis失败先保留已成功的PG投影，然后报告blocked，单一循环进入既有失败冷却；提交唤醒不能打断冷却。不把QUOTA_MISSING当成成功，毒前缀的技术过期仍须后续解决，当前保留Gateway CLOSE。

## 4. 最小充分验证

复用现Gateway JSON证据用例：暂停worker，成功HTTP已返回但无CLOSE命令、PG未关闭、租约仍ACTIVE；并发额度为1时下一请求不得发送。恢复处理后，在同一成功账务提交中关闭并转RELEASE_PENDING；停止原Gateway后仍能经另一Core的worker身份恢复到RELEASED，重复恢复为0，后续请求可重新发送，原金额与两份事实断言保留。

保留失败/取消的原集成用例、旧V1历史、吊销/冲突和组事务回滚用例。补一个公共恢复结果的定向用例，证明无过期permit时满批释放仍报告后续工作、短批停止。完整门禁与耐久/备份集中在可验收里程碑，不机械重复全部测试。容量收益仍须同构建两轮证明；未完成故障检查如实列出。

## 5. 仅配额技术过期

为补齐上述边界，在原worker恢复入口的同一权威调用中先推进技术过期。它不依据QUOTA_MISSING判定，不修改receipt、permit、attempt、客户或供应资金；只终结执行及配额。条件同时要求原request不可变execution_budget.deadline_at已过、全部已有permit已过expires_at且没有RESERVED、该request全部尚未终结的descriptor.deadline_ms已过。缺字段不补造，未授权调用仍由core_caller_v1拒绝。所有条件在request FOR UPDATE、排序的permit和lease NOWAIT锁下重核；next/BEGIN任一先取得锁都会使技术恢复退让，技术恢复先提交则它们遇execution_closed而拒绝。晚到真实用量仍可按原证据规则收取，UNKNOWN资金不释放。

有意新增的执行语义是原request总执行预算截止之后不得通过未来NEXT重开，不把它称为纯投影修复。不能仅看某次attempt过期就关闭仍有有效request预算或未来grant的执行。ACTIVE、ADOPTION_PENDING及RELEASE_PENDING均需涵盖，避免Redis tombstone在deadline+30秒消失后形成固定pending毒前缀。它们置EXPIRED而非伪造Redis RELEASED，descriptor、revision、Redis代际与实际key均不改；Redis并发容量仍由其原TIME/live_until自然过期或合法释放，RPM/TPM不退款。

追加普通schema迁移，为未终结租约的descriptor.deadline_ms、request_id、lease_id建立部分表达式索引，Drizzle及快照同步；不扫描全部已释放历史。每轮按到期索引至多取batch条租约，排序去重后最多处理batch个request。独立子事务遇锁冲突退让。Core store保存唯一有界三元组游标，每页后推进、尾部回绕；并发结果以版本比较避免迟到覆盖及ABA倒退。先截取固定前缀再过滤不能证明推进：合法短NEXT租约可在总预算未过期的request上占满前缀，现已用游标消除此阻塞，不能放宽资金或截止条件。

恢复先尝试原Redis释放并写入PG，再做技术过期，保留原never-granted abort的RELEASED语义；不能因绝对截止刚到就抢先把可正常释放项全部改为EXPIRED。成功Redis释放的完成项若恰遇另一Core已置EXPIRED，在全部身份/revision检查通过后作为幂等终态处理，保持EXPIRED及原descriptor，不使整个完成批次回滚。

响应增加expired（已过期request数，0–100）及expiry_more；后者只有扫描满页且有实际过期转换才为true，防无进展自旋。pending/failed只描述本轮实际选择的Redis释放集合；技术过期与released分开报告。

完成以上恢复并验证后，Gateway只在finish耐久成功且attempt/request均SUCCEEDED时省略CLOSE；错误、失败、取消、未发送和UNKNOWN路径继续原CLOSE。健康观测仍保留。低并发配额从原同步释放变为worker提交后恢复释放，依靠提交wake降低等待，但不宣称返回200的瞬间必可立刻发送下一请求；积压时拒绝或等待符合原限流契约，不能超发。
