# 04 需求规格与验收

2026-11-17 后续状态：用户已授权高性能、生产可靠性与扩展性改造，当前实施记录与单元验收见 [05-implementation.md](05-implementation.md)。原P0范围说明保留为历史，不再作为后续实现的停止条件；推荐技术方向由代理在既有不变量内落实，并不伪称用户逐项投票。

把 [02-architecture.md](02-architecture.md) 与 [03-server-design.md](03-server-design.md) 整理为可实施、可验收的需求。本规格不授权实施；D1–D6 裁决前，依赖它们的条目（标注“依赖 Dx”）不开工。

## 1. 问题与目标

本项目同机完整链路稳定负载 35 RPS，new-api 为 2500（预扣）/ 3000（默认）RPS；每请求 CPU 约 41 ms 对 1.4 ms（[01-baseline.md](01-baseline.md)）。完成后：

- 完整链路稳定负载 ≥ 3000 RPS，并在请求性能与并发性能上超越同日 new-api 参考；持平不算完成（G1、G2，用户在P0中确认目标）。
- 每请求 CPU ≤ 2.0 ms（G3）。
- 以同一套故障注入量化证明资金正确性强于 new-api（G4）。

## 2. 范围与非目标

范围：Core 准入、begin、结算数据路径；身份、Key、目录的缓存与栅栏；供应额度单元；成功路径收尾；内置适配器执行路径与多帧 ABI；PG 耐久配置；容量与对标装置；故障对照。

非目标：商业控制台与支付；新协议与新供应商；降低耐久或预扣；跨故障域 HA。

### 3.2 Core 数据路径（P1–P4）
