# 超越 new-api：3000 RPS 完整方案

2026-11-17 后续状态：用户已授权高性能、生产可靠性与扩展性改造，当前实施记录与单元验收见 [05-implementation.md](05-implementation.md)。原P0范围说明保留为历史，不再作为后续实现的停止条件；推荐技术方向由代理在既有不变量内落实，并不伪称用户逐项投票。

2026-11-17。状态：实施中，最终目标未达到。P0装置、基线及剖析已完成；当前阶段和失败记录以05为准，原D1–D6保留为设计来源。

## 结论

- 原测为35 RPS、约41ms CPU；P0重测为35 RPS、约45.46ms。S2d已测构建连续两轮40 RPS、约35.98ms，尚远未超过3000。new-api默认3000、trust=0但实际零预扣2500、用户追加的真实正额预扣3000三配置分列，详见[P0报告](../docs/performance/p0-2026-11-17.md)。
- v2实测成本包括5次Core RPC、逐项准入及身份重核、SQL候选摘要、供应余额单行锁和逐调用QuickJS-Wasm实例。历史单体2000–3951 RPS不能代替当前逐ID交集及完整资金契约的证明；改造须通过同一验收装置核对收益。
- 方案保持三进程、预扣、WAITAOF、上游硬闸与吊销线性化不变，通过集合式批处理、修订号栅栏、额度单元、成功路径收尾合并、内置适配器进程内执行，把每请求 CPU 压到 ≤ 2.0 ms，目标稳定 ≥ 3000 RPS，并在请求性能与并发性能上超越 new-api（持平不算完成）；再用故障对照证明资金正确性更强。
