# 从零建设与验收

本计划从空仓库/空数据库建设，没有改造、回填或迁移任何现有项目。后端技术栈已确定为 Bun + TypeScript，具体运行时/驱动锁定版本须在开工时做兼容验证，见 [Bun 运行规范](bun-runtime.md)。

## 1. 建设阶段

| 阶段 | 交付 | 完成条件 |
| --- | --- | --- |
| A0 工程基线 | Bun workspace、strict TS、运行时 schema、金额编解码、独立进程与版本锁定 | tsc/lint、Bun.SQL 真 PG 精度/事务/断线、流背压/取消探针通过 |
| A 金融内核 | Money/价格、账户/effects、journal、预留/slices、幂等回执、现金充值 | 真 PG 约束、并发、重复与提交未知测试通过 |
| B 订单与调用 | 业务幂等、原子 AdmitAndPermit、owner/载荷许可、provider allowance | 未获新许可不能发送；同键不重复获得发送权 |
| C 单供应商闭环 | 一个经认证连接器、非流式/流式、SealEvidence、Capture | 正常交付前证据耐久，费用与预留/账本一致 |
| D 恢复与风险 | UNKNOWN、截止政策、NO_CHARGE、供应商应计/准备、对账/审批 | 晚到结果不复活用户收费，成本预算不凭空恢复 |
| E 路由与产品 | 多供应商、严格过滤、评分、统一重试预算、组织/可选权益来源 | 每次物理发送有成本责任，产品替代/计量正确 |
| F 运行保障 | HA、grant/return、支付/退款、资源隔离、归档与恢复 | 故障与权限验收、对账覆盖/值班手册通过 |
| G 容量放量 | 单组/多组、长流/热点/故障/存储测试 | 通过代表性 10k+ 验收后才声明容量 |

阶段可按风险拆交付，但不能在 B/C 未完成时上线一个“先统计以后扣款”的公网计费 demo。Optional 功能未完成就关闭入口，不以占位成功返回。

## 2. 规则与数据库验收

| 场景 | 期望 |
| --- | --- |
| Money 边界、极小费率、多维/分母、拆分与舍入 | 全请求一次精确有理数→atoms，退款不多退、无浮点 |
| 多并发意图争同一 cell | posted>=reserved，授权不重复占用同份本金 |
| root 补给/回收与请求并发 | 本金不复制，余额汇总不重复包含已划拨额 |
| 相同业务键/commandId 100 并发 | 一份订单/预留/许可；同键异参冲突 |
| journal 不平衡、跨资产、错误归属、旧 header 补腿 | 由实际约束/权限拒绝 |
| effect 序列错、reserved_delta 与 slices 不符 | 提交拒绝，不能修改余额缓存绕过 |
| Capture/NO_CHARGE/重复工作并发 | 唯一原始决策，不重复扣款，不捕获已免收订单 |
| 金额 C>R、供应商 K>Kmax | 用户不透支，外部真实成本不丢，异常配置停止新调用 |
| 来源到期/成员退出/周期跨日 | 原预留按固定政策处理，不悄悄换来源或复用限额 |
| 原收费退款与收入条带变化 | 回原对手/来源、累计不超原实收 |
| grant 重投、接收确认丢失、return 重复/乱序 | 已发/在途本金不被第二次使用 |

数据库测试必须用匹配生产版本的 PG；内存模型只能验证规则，不证明锁、隔离、FK、触发器和 COMMIT 行为。

## 3. 端到端故障验收

| 注入点 | 必须观察 |
| --- | --- |
| Admit/Seal/Capture 每条语句后失败 | 全部回滚或完整提交，不留下孤立 slices/effects |
| COMMIT 后丢失响应 | 旧 command 可查，重放无新发送能力 |
| 许可已发、执行节点崩溃/暂停再恢复 | 不透明重发；用户与供应商责任按独立政策收口 |
| 首字节前 timeout、5xx、空响应 | 每次真实发送被登记，未知不按错误码免费释放 |
| SSE UTF-8、CRLF、多行、正文/usage/DONE 同块 | 正确增量解析；正常完成等待耐久证据 |
| SealEvidence 时 PG 失联/客户 AbortSignal 已取消 | 不假正常完成；已有业务资金事实保留 |
| 客户慢读、停止读取、大输出 | 缓冲有界、取消正确、不拖垮其他租户 |
| 未知先过期免收，再来最终结果/发票 | 用户仍 NO_CHARGE，供应商成本有独立处理 |
| 创建远端媒体任务后存号失败 | 不创建第二任务，原订单进入未知恢复 |
| Redis 清空/网络分区 | 降载/重建软状态，金融工作照旧可查 |
| 同步候选故障/旧主网络恢复 | 安全停止新金融提交、无双主许可、已确认记录不丢 |
| 支付/退款响应丢失 | 同业务身份查询，资金冻结不乱释放、无重复支付 |
| PITR 恢复 | 冻结新许可，外部事实核对后重新开放 |

供应商假体必须模拟“已产生费用但响应丢失”，不能所有失败都实现成未执行；否则永远测不出重复供应商成本。

## 4. 容量验收

1. 单资金组使用完整 Admit/Seal/Capture、真实索引/约束、同步复制和预期活跃预留集，测 CPU/IOPS/WAL/锁/触发器成本。
2. 集群持续至少 60 分钟成功受理/执行 10,000 请求/秒，且正常最终证据和收费率跟上，不把快速拒绝计成功。
3. 纳入真实分布的 TTFT/时长、消息/文件/输出大小、token/单位数、付款账户热点和共享 provider account。
4. backlog 无持续增长，测试结束在约定时间追平；所有 journal/effects/预留/allowance 对账一致。
5. 健康依赖初始目标 pre-upstream p99≤30ms、Seal p99≤50ms、正常收费 p99≤5s、合格成功率≥99.9%；若硬件/同步 RTT 不支持则先调整部署或明确变更目标，不能忽略统计。
6. 建议 15k/s 突发 10 分钟：允许有界拒绝，但不能 OOM、无限内存排队或丢金融事实。
7. 同时测试故障中的吞吐/未知金额/恢复速度和备份/WAL/归档追平，不只测一次短跑 RPS。

补充 Bun 验收：锁定 Bun/OS/CPU 架构和依赖，独立执行 tsc、lint 与 bun test；实际慢读/断连/长静默/停机排水不能只用内存流模拟。采集事件循环延迟、RSS/堆/外部缓冲、CPU 与单进程/多副本曲线，验证大 JSON、tokenizer 和日志峰值不会阻塞全进程。Bun.SQL COMMIT 失联、numeric(38,0) 往返和 BigInt DTO 单列验收。

单个付款账户万级压力必须单列。多数随机账户合计达标不等于一个热钱包/一个硬限额根行也能达标。

## 5. 必须定稿的业务参数

| 参数 | 本文默认/建议 | 定稿依据 |
| --- | --- | --- |
| 证据政策 | 默认 FINAL_ONLY，估算另立产品政策 | 客户合同、供应商能力 |
| 用户未知处置 | 有期限后 NO_CHARGE，原供应商责任不清零 | 产品时限、平台风险预算、反滥用 |
| 产品/模型替代 | 默认只同语义产品供应商替换 | 能力/质量/地域验证，客户显式许可 |
| 用户信用 | 默认不透支 | 后付费须独立批准与应收模型 |
| 来源 | 首发 CASH；权益来源按功能阶段启用 | 资金属性、有效期、可退规则 |
| allowance 大小/低水位/cell 数 | 不在文档编造硬件值 | 完整单组与热点负载基准 |
| 物理资金组数 | 按测得容量和故障余量 | 单组性能、地域和组织聚合 |
| 留存/地域 | 金融最小证据与内容原文分离 | 适用政策与实际存储/恢复成本 |
| 运行时/驱动版本 | 开工锁定受支持版本 | Bun/TypeScript/@types/bun、Bun.SQL、Redis 客户端和协议兼容测试 |

这些是新系统正常的实施输入，不要求用户提供旧项目表结构或旧兼容窗口。
