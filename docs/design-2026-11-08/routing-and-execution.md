# 智能路由、调用许可与流式执行

路由只选择符合合同的执行路径，不决定扣款/退款。每次收费性物理发送必须先取得 Finance 的新许可，执行节点不得绕过这一点调用连接器。

## 1. 请求准备

每次 HTTP 生成 ingressId，完成体积/深度/文件大小与鉴权预筛。先查询已存在业务意图：重试不因当前调价、模型下架或默认参数改变而重新计算成另一个业务。

新意图构造 canonical request，固定产品、用户价、所有输出/单位上限、能力、地区、客户最大费用与允许的模型替代范围。JSON 对象键可规范化但数组顺序保留；multipart 文件用增量内容摘要，不用 JSON.stringify(FormData) 充当载荷身份。

连接器准备最终出站模型、供应商参数、系统/工具结构、签名需要的载荷和计费上界。金融许可绑定其 outbound_fingerprint 与 connector version。签名时间等非业务字段可按协议更新，但不能借此改变模型、内容或费用上限。

## 2. 候选硬过滤

按以下顺序先过滤：

1. 产品与凭证 scope、组织/成员用途。
2. 模型语义等价、上下文窗口、工具/JSON/视觉/音频等能力。
3. 地域/数据出境约束、客户允许的供应商范围。
4. 供应商启用状态、凭证版本、端点安全策略。
5. 本计费维度的可验证用户/供应商费用上界。
6. 恢复能力要求：最终用量、幂等、账单与未执行证明分别判断。
7. 共享 provider account 的 RPM/TPM/并发软许可，以及本资金组 allowance 的保守可用提示。

无候选时不发上游。缓存提示可提前筛选，但最终资金/allowance 由 PG 原子条件检查；缓存旧值不会赋予花钱权限。

同名模型不自动视为等价。跨模型降级只有客户明确 allow_model_fallback，且响应/账单显示实际履约产品；不能悄悄返回便宜模型再按原模型假装完成。

## 3. 排序与流量分配

优先级表示运营约束，按高到低分组；只在允许的组内做无放回加权选择。

```text
effective_weight = configured_weight
                 × health_factor
                 × latency_factor
                 × queue_factor
                 × cost_factor
                 × affinity_factor
```

各因子有界，避免接近零造成永不探测、或一个过大 sticky 权重淹没其他约束。成功率/TTFT 用有最小样本量的滑动/EWMA 指标，低样本采用保守先验和独立少量探测；不存在健康样本时不直接全量放行。

成本因子比较该请求的估计进货费用，不只比较“inputPrice+outputPrice”；长输入、长输出、缓存、媒体和单位计费分布不同。路由权重可用浮点近似，金融费用/预算必须精确 Money 计算。

会话亲和基于付款账户/产品/受限会话摘要，期限有限，只是偏好。它不能绕过地区、能力、预算或 OPEN 熔断。配置版本与实时评分时间/选择理由分别留痕；只存版本号不足以重放当时的实时选择。

## 4. 同一请求的执行预算

请求总预算包含：物理发送次数、连接/首包/空闲/总截止时间、允许换候选次数、等待时间与最大可占用资源。建议初始最多 3 次物理调用，参数按产品发布并记录快照。

所有收费性重试由同一编排器负责。HTTP 客户端、SDK、连接器内部不得再悄悄重试；无副作用查询可有独立有限重试。每次同渠道第二次 POST 也创建新 invocation，并预留自己的成本。

运行许可与金融预留分开：先拿有界上游/租户运行许可，再申请金融许可；金融拒绝归还运行许可。请求不能持有 PG 连接等待运行许可、供应商响应或网络发送。

## 5. 新许可与重复命令

`AdmitAndPermit` 在同一资金组事务内创建新业务意图、预扣、provider allowance 和 MAY_HAVE_EXECUTED invocation。调用前所有可能的收费要有归属。

只有事务明确新建且耐久提交确认，Finance 才向指定 owner 返回一次 CREATED_PERMIT 和受限发送 token。执行节点对该 owner/命令只有一个发送任务；连接器检查 token 与最终载荷摘要后只调用一次。

再次请求同一命令/业务键，返回稳定 order/decision 的 OBSERVE_ONLY，不返回可发送 token。即使首次响应丢失而实际上没发出去，也不能凭查到旧许可重新发送；保守地进入未知恢复。

供应商不校验本地 token，因此不能据此宣称外部绝对恰好执行一次。安全保证针对可信执行代码的正常故障；内部恶意持有明文供应商 key 的进程需要额外网络/密钥治理。

## 6. 错误处理与切换

| 情况 | 确定性 | 处理 |
| --- | --- | --- |
| 本地参数/权限/余额/健康门拒绝，未获许可或未发送 | 可证明未执行 | 拒绝或尝试其他候选；不占物理调用次数 |
| DNS/建连失败且传输层有明确未发送证明 | 未执行 | 先关闭旧 invocation 与成本预留，再在总预算内尝试 |
| 429、401/403、部分 4xx | 取决于供应商契约 | 明确未执行才可切换；记录真实配额/凭证故障范围 |
| timeout、EOF、连接重置、5xx | 默认未知 | 不自动换渠道；保留旧成本责任 |
| 供应商已返回任何业务内容 | 已开始履约 | 不透明拼接另一调用；中断/用量由当前调用收口 |
| 200 空内容/不合法 JSON/流内错误 | 可能已执行 | 不能因为“用户没看到内容”自动认定未计费 |
| 最终证据保存失败 | 本地资金事实未完成 | 不重发供应商请求；同证据有限重试或未知恢复 |

NOT_EXECUTED 的确认是可审计证据和旧发送者实际结束/隔离，不是一个通用错误词表。查询“暂时找不到”也不是最终未执行证明。

安全重试还需要完全可重放的载荷。一次性流式上传、消费完的 multipart、过期 URL 或不可再取的文件不满足该条件时停止，不拿空文件或重建内容替代。

供应商端若提供真正的幂等恢复，可以用原 invocation 的供应商键和原载荷继续查询/恢复；必须覆盖作用域、保留期、状态未知时的响应和流输出可否重放。不能把本地订单号塞进普通头就声称具备这项保证。

## 7. 流处理与终态屏障

执行节点使用 Bun.serve / fetch 和 Web Streams 建立一条有背压的读取/写出管线，同时增量观察计量。慢客户写出阻塞时不无限提前读取供应商，不用快分支 tee 吞完数据后在内存缓存整条用户流。

协议解析处理 UTF-8、CR/LF、跨块事件、多行 data、压缩/翻译后的大小、流内错误与各供应商不同的结束标记。字节块不是 SSE 行；不能按一次 read 的 split 结果直接 JSON.parse。

终态过程：

1. 按连接器规则确认最终计量与结束边界，不把最近一次累计 usage 当最终值。
2. 暂存受限的终态事件窗口；非终止正文已按背压发送。
3. 使用服务生命周期管理的独立 AbortController 和收尾 deadline 调用 SealEvidence，不能沿用已取消的客户 request.signal 导致写证据必然失败；收尾 Promise 必须被在途登记器等待或转为 PG 已知的恢复责任。
4. 提交成功才转发正常完成标记/关闭；失败则明确错误或异常结束，保留已产生费用的未知状态。

同一个 chunk 可能同时包含正文、usage 和 DONE；必须按事件边界切分，不能先透传整块后再保存。非 SSE、二进制或异步任务也要定义“成功交付边界”，不能只为 OpenAI chat 做屏障。

Web Streams 的 pull/desiredSize 或 writer.ready/write 用于传递需求；highWaterMark 按字节计数，事件解析缓冲另设硬上限。不能在 start 中无条件循环 enqueue，也不能用 response.text()/json()/arrayBuffer() 收集完整长流；小型 JSON 响应也必须先做体积限制。Bun 的长流空闲超时与 LB/入口超时共同显式配置，并保留产品级流空闲/总期限，不能只关闭所有超时。细节见 [Bun 运行规范](bun-runtime.md)。

初始保护值可以采用 256 KiB 待转发缓冲、1 MiB 事件窗口、30 秒慢客户无进展上限，均需按媒体/工具协议验证和调优。限制在所有执行节点统一配置，超限清晰失败，禁止静默截断账务证据。

## 8. 取消、长流与异步任务

用上游 AbortController 处理客户断开与各类 deadline，reader.cancel/abort 不证明供应商未执行；清理计时器和 reader 锁，所有拒绝路径被等待和归因。连接超时、响应头、首业务字节、流空闲、总产品期限与客户断开是不同原因。不能用一个 60 秒 timer 覆盖所有长流；总期限由产品能力固定并计入调用许可。

客户断开优先取消上游，必要时允许短时有界 drain 收取最终证据；取消响应不代表费用为零。已有可信最终证据仍封存。没有最终证据时，按固定 policy 走估算或 UNKNOWN；不在故障发生后临时选择对平台最有利的计量。

异步媒体任务：创建远端任务也先登记 invocation。保存 provider_task_id、最终输入/价格/计费单位和查询策略，再返回稳定 jobId；创建成功但本地存号失败属于未知外部任务，不能自动再创建一次。业务 job TTL 到期不证明供应商取消/免单。

如需要本地排队后执行，采用明确的两阶段变体：EnqueueOrder 先绑定意图、固定报价/期限并预留客户资金，写 execution task；执行节点领取任务后调用 PermitQueuedInvocation，在事务中复验原预留仍有效、占供应商额度并授予一次新发送权。QUEUED 时客户取消与发送认领锁同一订单；取消赢则不能再授予许可，许可赢则按可能执行处理。任务领取租约可以重复，已提交外部许可不能因任务租约到期再次发送。长时间上游执行不放进 Financial Worker 的连接/任务池。

对媒体产物链接/临时下载，保留可核对的 artifact 元数据与受控访问策略；生成成功与用户下载成功不是同一计费事实。

## 9. 熔断与 Redis 故障

CLOSED→OPEN→HALF_OPEN→CLOSED；凭证配置错误可单独 DISABLED。打开条件有合格样本数/失败率窗口，半开探测有少量原子许可，恢复渐进放量与抖动。

用户参数错、单请求过大、用户资金不足不能污染供应商健康；429 按真实账户/组织配额域冷却，避免多个 endpoint 同时恢复冲击。Retry-After 有界应用，不突破本请求 deadline。

Redis 不可用时：停止不确定的动态放量，按预先下发的实例份额保守工作或拒绝；不能每个副本各自用全局额度。PG 用户/供应商金融预留继续保证金钱边界，但不能拿它承诺所有运行配额绝不超限。

## 10. 扩展要求

新连接器必须通过：能力/上界/计量维度、最终与累计 usage、错误执行确定性、取消、任务、同载荷恢复、账单域、SSE 边界、原始证据和成本快照测试。缺失能力默认不支持，不由控制台勾一个标志后未经验证启用。

路由观测统计需要区分候选被门拒绝、取得许可、真实发送和最终成功；只用外层 attempt 次数会漏掉 SDK/HTTP 自动重试，必须用受控出站的物理发送事实校验。
