# Gateway 生产稳定性验收 · 2026-11-25

范围包括推理吞吐、尾延迟、SSE 完整性、上游失效与账务恢复。对照是本机 `work/new-api` 的 `ce8fc49e4` 构建，Gateway 基于 `ea36a09` 加本轮修改。参考工作区只读，两侧运行在独立的本地实验环境。

## 短负载对照

同一台 Apple M6，原生 PostgreSQL 17.11 UTF-8；`fsync`、`synchronous_commit`、`full_page_writes` 均开启。每轮创建独立数据库并使用独立的 Redis 命名空间或实例。两边使用 64 个数据库连接上限、1,000 个轮询钱包、一个共享构建的模拟上游和同一个 Bun HTTP/1.1 发生器。每档 8 秒，提前预热连接。`new-api` 采用 `trust_quota_usd=0`，额外测 5 秒内存批量模式。所有流量向本地测试监听发出。

## 60 秒持续负载

两边单实例、512 并发短 JSON，各运行约 60 秒。保持同一负载、连接上限和预扣配置。Gateway 压测关闭访问日志，`new-api` 保持其运行日志设置。

| 实例         | 成功 RPS | P99 ms | 计量期成功数 | 错误数 |
| ------------ | -------: | -----: | -----------: | -----: |
| Gateway      | 17,561.9 |  47.44 |    1,054,110 |      0 |
| new-api 默认 |  2,109.5 | 561.32 |      127,370 |      0 |

Gateway 本轮吞吐为对照的 8.33 倍。两侧这轮账务核对通过，Gateway 包括预热共 1,079,293 笔唯一结算，活跃租约归零。原始数据位于 `.local/compare-newapi-20261125/` 下各轮 `audit.json`。

最终产物在 1,024 并发再次通过短负载，JSON 为 18,914.5 RPS、P99 71.62 ms，SSE 为 12,413.4 RPS、P99 107.10 ms。两轮共 297,778 笔唯一结算，零请求错误、守恒通过、活跃租约归零。

## 故障演练与上线边界

- 本轮 162 项单测、117 项真实 PostgreSQL／Redis／HTTP 集成测试通过。类型、Lint、格式、OpenAPI、隔离构建和独立产物验收通过。
- 100 个客户端都在上游完成前收到首块流数据，再取消真实 HTTP 请求。模拟上游观察到 100 次取消，活跃生成归零，渠道仍可用。覆盖全量缓冲和客户端断开后继续占用上游的两类风险。 [Kong #12680](https://github.com/Kong/kong/issues/12680) · [SGLang #46517](https://github.com/sgl-project/sglang/issues/46517)
- 隔离 PostgreSQL 主备演练中，8 笔已确认交易无丢失，推理约 5.75 秒恢复。Redis Sentinel 提升后，入口配额约 2.44 秒恢复；副本保留已复制计数，按演练设计丢失 1 笔未复制更新。PITR、强杀恢复和逻辑备份恢复均通过。
- Caddy 28 项路由检查通过。限额 Linux 容器中 CPU、内存分别触发入口 503。隔离演练覆盖插件跨节点发布、确认和撤销。
- 初次本机复核发现 `api.minimax.cn` 的解析包含保留 IPv6 `2001:2::45`，Gateway 拒绝拨号。后续本地部署时系统解析已恢复，复验结果见下节。实际生产网络和跨故障域尚未验收。

## 本地部署与真实 MiniMax 复验

已验收构建部署到 `127.0.0.1:8088`，使用本地 Docker PostgreSQL 和 Redis。部署前的 Clash 用户配置已在 `dns.fake-ip-filter` 中精确列出 `api.minimax.cn`，历史保留 IPv6 落在该配置的 `fake-ip-range6` 内。Gateway 按系统解析得到 5 个公网 IPv4 地址，真实请求通过 TLS 证书和域名验证。受控 DNS 复验同时返回公网 IPv4 与历史保留 IPv6，仍在拨号前返回 `unsafe_upstream`。未修改系统 DNS、固定供应商 IP 或放宽地址校验。DNS、地址限制和 TLS 回归共 5 项通过。 [Mihomo DNS 配置](https://wiki.metacubex.one/en/config/dns/#fake-ip-filter)

真实 `MiniMax-M3.1-Flash` OpenAI 兼容入口验证了 JSON 和 SSE。

| 场景                   | 成功次数 |     P95 |
| ---------------------- | -------: | ------: |
| 10 分钟，每 10 秒 1 笔 |    60/60 | 3.83 秒 |
| 6 分钟，每分钟 20 笔   |  120/120 | 3.59 秒 |
| 2、4、8、16 路并发     |    30/30 | 6.86 秒 |

16 路单档 P95 为 6.99 秒。含冒烟和故障演练在内，222 次 Gateway 请求中有 218 次真实推理成功并唯一结算，另有 1 次 Redis 故障期间拒绝、2 次幂等重放和 1 次预扣拒绝。按响应计量与入账价表逐笔核对，客户共扣款 0.037302 USD，账本供应商成本共计 0.0149208 USD。两侧分录均平衡，试验 Key 的实扣等于逐笔合计，余留预扣和新增 `UNKNOWN` 均为 0。供应商成本按本地账本核对，供应商独立账单未纳入。原始证据位于 `.local/minimax-agent/live-acceptance-20261125/` 下的 `summary.json` 和 `requests.jsonl`。

隔离 Redis 停止时请求返回 503，没有预扣、上游调用或实扣。进程重新启动后约 215 毫秒恢复就绪，恢复后的真实 SSE 正常结算。主 Gateway 在有一条真实 SSE 请求时收到 SIGTERM，该请求完整结束并结算，新进程约 4.03 秒就绪。使用相同幂等键重放返回 409 和原请求 ID，该请求仍只有一张账单。首次脚本误将原请求的账单视为重放产生的新账单。更正断言并复测后，两个重放都核实无新增扣款。

补测 Anthropic 兼容入口时，当前测试 Key 的消费上限不足以覆盖预扣，Gateway 在发往上游前返回 402，未留下预扣或账单。全库另有 8 笔 11 月 24 日其他 Key 的历史 `UNKNOWN` 预扣，账本无扣款记录，仍待供应商证据。

## 长 SSE 与并发容量补测

真实 `MiniMax-M3.1-Flash` 首轮运行 20.96 秒，结算用量为 3,072 个输出 token，其中 3,071 个为推理 token。流收到一次计量帧和一次 `[DONE]`，正文为空，未达到正文验收门槛。改用简单叙事提示后并发验证两条正文流，分别运行 18.67 秒和 9.42 秒，首正文为 2.19 秒和 1.93 秒，收到 148 和 68 个正文帧。两条流均完整返回到 token 上限，终态为 `length`，每条恰好一次计量和一次 `[DONE]`。三个真实请求各结算一次，共扣款 0.0219775 USD，账本供应商成本 0.008791 USD，测试 Key 实扣增量对齐、预扣归零。

同一构建在两个隔离 Gateway 副本上冷建 4,000 条 SSE，每条上游持续 120 秒。全部成功，同时在线约 114.02 秒，首正文 P99 为 5.04 秒，双副本峰值 RSS 为 507.4 MiB。共收到 160,000 个正文帧，逐笔唯一结算，金额零差异。结束后 Gateway 和模拟上游活跃流、Redis 并发许可、账本活跃租约均归零。

8,000 路两次分别完成 7,994 和 7,989 条，均未达到全量验收。第一轮 6 条返回 503，复跑 11 条明确返回 `503 upstream_capacity`。已接通的请求全部返回有效的内容、计量与结束帧，账单逐笔一致，没有遗留许可或待核账预扣。未留出 TCP 回收时间就接续运行 7,500 路时，仅完成 3,574 条。2,507 条收到 Gateway 的本机上游套接字容量 503，1,419 条在客户端建连时直接收到 `EADDRNOTAVAIL`。本机端口范围为 49152–65535。

TCP 连接回收后复跑 7,500 路，双副本各接收 3,750 条，建连分批发起约 7.6 秒。每条上游持续 120 秒，7,500 条全部完成，同时在线 109.03 秒。首正文 P99 为 1.73 秒，双副本峰值 RSS 为 618.6 MiB。7,500 笔逐笔唯一结算，金额零差异。满载时额外 128 笔请求全部返回 `503 overloaded`，上游调用、预扣和扣款均为零。排空后 16 笔探针全部成功，Gateway 和模拟上游活跃流、Redis 并发许可与账本活跃租约均归零。汇总与原始日志位于 `.local/minimax-agent/long-sse-20261125/`。

## 8,000 路复验与 Key 到期修复

隔离压测将客户端至 Gateway 改为 IPv6 回环 `::1`，Gateway 至模拟上游保留 IPv4 回环，两组连接使用不同本地地址。与前一轮相同的 Gateway 构建连跑两轮，每轮 8,000 条长 SSE、每条 120 秒，16,000 条全部完成并逐笔结算。两轮满并发重叠约 109 秒，首正文 P99 分别为 1.24 秒和 1.25 秒。每轮额外 128 笔返回 `503 overloaded`，无上游调用、预扣或扣款。每轮结束后 16 笔恢复探针均成功，活跃流、Redis 许可和账本活跃租约归零。验证仅覆盖本机隔离双副本，生产网络仍需对应环境的容量数据。

临时 Key 复验发现 Bun SQL 返回的 `Date` 经 Drizzle 字符串映射后，UTC 时分秒与进程本地时区偏移被拼接，导致 Key 到期时刻漂移。账本只将 Key 的到期字段按 `Date` 读写，对外仍使用 UTC ISO 字符串。数据库原列为 `TIMESTAMPTZ`，无需迁移。真实 PostgreSQL 回归覆盖新加坡时区的新 Key 可用，以及洛杉矶时区的已过期 Key 返回 401。修复前回归失败，修复后通过。

原 Key 的消费上限为 0.0733775 USD，当前 Anthropic 路由按价表对这类测试请求预扣 0.150512 USD，所以 402 符合现有配置。用按价表核定上限、仅本机和指定模型及入口可用的临时 Key 复验，真实 MiniMax 的 JSON 与 SSE 均返回 200。两笔共扣 0.000318 USD，账本供应商成本 0.0001272 USD，预扣归零，临时 Key 已禁用。

历史 8 笔已按请求与 Gateway 日志逐一归因，4 笔客户端取消，4 笔上游超时。客户预扣共 1.331072 USD，供应商预扣共 0.5324288 USD，实扣为零。现有记录缺少可关联到这 8 笔的供应商最终回执，因此保留待核账状态。原始复验证据位于 `.local/minimax-agent/connection-retest-20261125/`。
