# 0008 完整资金链路的性能与生产可靠性

> 版本说明。本文记录 2026-11-17 的容量改造及当时的三进程边界。当前系统与验收入口见 [ADR 0009](0009-enterprise-gateway-worker-architecture.md) 和 [容量及对标契约](../performance/capacity-contract.md)。

2026-11-17。状态：实施中，最终验收未完成。设计与阶段证据见 [beyond-new-api](../../beyond-new-api/README.md) 和 [实施记录](../../beyond-new-api/05-implementation.md)。

## 目标与边界

按相同固定到达模型、请求和上游条件，完整链路稳定吞吐严格超过3000 RPS，并超过同日new-api参考；同并发度比较吞吐、成功率和P99。总服务端CPU目标为每请求不超过2ms，包含Gateway、Core、worker、插件helper、PG和三类Redis。局部进程优化或HTTP成功率不能代替完整交集、逐项资金核对和证据耐久性。

保留Gateway/Core API/Core worker边界、Gateway不访问PG、首次attempt与客户预扣原子提交、供应预付硬闸、UNKNOWN资金责任、命令和意图幂等、身份吊销线性化、成功前WAITAOF及worker提交后ACK。PG三项耐久设置保持开启；证据AOF always并取得副本确认。禁止用放宽容量契约、跳过收费或减弱权限换取吞吐。

用户最初只授权P0，后续已明确授权高性能、高可用、生产可用和可扩展实现。代理在既有业务不变量内采用推荐工程方向，不将该授权描述为用户对D1–D6逐项投票。60分钟长测仍需后续明确授权，真实部署与外部付费操作也不由本决定授权。

## 当前落地的决定

1. SDK通过私有拥有字节和不可伪造的模块句柄，将签名验证后的模块哈希及完整包复制移出每次插件调用。公开可变副本不能改变执行内容；helper驱逐、重启、取消、预算和第三方隔离继续生效。
2. Core中间件缓存有界peer/session预读，只服务密码证明与提前拒绝。每项业务仍经PG权威状态和锁；通知丢失不扩大授权。共享冷加载有独立owner期限，每个等待方可独立取消。
3. 批内按完整九字段身份元组重核和持锁。成功身份锁在任何item子事务前提升到外层，item回滚不能释放已复用的授权栅栏。每项期限和自然过期仍实时核对。
4. 私有目录候选缓存以事务内集合epoch共享锁作为warm读取的语义栅栏。全部语义来源同事务失效；cold使用来源关系及行NOWAIT锁。缓存4096行、逻辑payload64MiB，超预算计算但不缓存，原候选集合、金额与摘要算法不变。普通资金余额变更不失效目录。
5. 完整request租约查询使用非唯一request前缀索引，原公共scope部分唯一约束保留。索引只改变访问成本，不修改授权、租约释放或资金判定。
6. 空闲 Batcher 在 microtask 合并同步项后立即发起。资金预扣和结算队列在相邻请求间隔落入已配置的收集窗口时合批，窗口从首个待处理请求开始，批量上限达到时提前提交。最后一个批次结束后，有待办且收集窗口已结束时立即继续。输出由所属事务提交结果决定。
7. UsageConsumer退出预算覆盖处理完成后的Redis ACK窗口；超时后关闭连接并依赖已有重投及PG幂等恢复。迟到的排空过程不得恢复连接或遗留计时任务。

## 后续设计约束

begin当前的钱包和供应余额写锁同时保护冻结、授信、已预留资金和最后发送条件。仅把状态读取改为KEY SHARE不足以阻止普通UPDATE；替代栅栏和两种先后交错未经验证前保留现锁。集合资金批和供应额度单元必须覆盖拒绝隔离、批内重复、账本恒等式、超预估冻结、重放及恢复。

仅由Core验MAC再向PG提交自选主体的无状态context方案扩大了受限SQL角色能力，不能实施该捷径。后续须由PG独立验证标准MAC，或通过重复客户凭证派生的verifier重新定位主体和权威目录。全部资源、batch、恢复、配额、命令和历史IP引用迁移前，保留现有持久context。

进程内适配器只允许受平台发布信任且与随构建源码、模块及元数据精确对应的包，第三方继续沙箱执行。需完整差分fixtures、状态隔离、取消与预算证据，不能仅按插件名选择执行器。当前尚未实现该路径。

生产高可用须分别证明PG同步复制与旧主fencing、证据Redis可晋升成员及水位约束、准入状态丢失关闭和恢复、滚动升级、密钥及备份恢复。单机耐久、逻辑备份或进程重启测试不等于跨故障域可用性证明。

## 迁移与验收

沿现有quiesced升级入口追加带校验值资产和Drizzle快照，不重写已发布迁移。建索引需要维护窗口；未在共享原生运行库执行迁移。回退依据迁移前备份及实际恢复验证，不隐藏或丢弃既有工作。

每个垂直单元先取得相关回归和独立只读审查，再运行仓库门禁、容量与耐久验证。失败轮次保留。现阶段尚未证明3000以上、CPU目标或生产HA；最新结果和未完成项随实施记录更新。
