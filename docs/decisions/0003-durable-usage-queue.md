# ADR 0003：BullMQ 严格落盘用量入口

状态：2026-11-10 用户确认，迁移实施中；覆盖 ADR 0002 的请求侧 PG usage/outbox 提交路径。原资金规则、无 LLM 正文持久化和独立业务边界保留。

## 基线与目标

基线：请求 PG 预扣/attempt → 上游 → PG usage/outbox → BullMQ 调度 → PG 结算。完整账务短测四实例、1000 钱包约 3624 HTTP RPS，仍有约 9.8 秒结算排空；不满足 10000+ 持续结算目标。证据保存在 `.local/phase2`，不是生产可用性证明。

目标：请求 PG 预扣/attempt → 上游 → BullMQ 数字证据入队并确认落盘 → 交付正常成功终态；worker 同事务写 PG usage/客户结算/资金流水，提交后确认作业。请求不再同步写 usage/outbox。PG 仍为资金与最终证据权威，Redis 为尚未入库用量的耐久入口。

## 迁移矩阵

| 单元           | 保留                                 | 有意变化 / 验证                                                         |
| -------------- | ------------------------------------ | ----------------------------------------------------------------------- |
| 预扣与 attempt | PG 原子权限/余额/幂等校验            | 保持调用前执行，不能把零余额检查移成最终结算                            |
| 内容旁路计量   | 白名单数字、精度、原生/转换语义      | 不把正文放进队列；队列 payload 必须严格 schema 校验                     |
| 入队确认       | 成功终态前耐久确认                   | BullMQ 入队后同连接落盘确认，超时结果未知，不报告正常成功               |
| Worker         | 幂等结算、缺失证据待对账             | 同一 PG 事务写 usage 与账务；ACK 必须晚于事务提交                       |
| 恢复           | 无重复上游执行、未知保留预扣         | 从未结清预扣索引发现遗留；队列完整丢失无法重建 usage，不可伪造为零      |
| 资源补证/冲突  | 原供应商归属、最终交付绑定、争议冻结 | 入口统一走耐久证据队列，兼容晚到和重复事实                              |
| 生命周期       | 有界资源与停机恢复                   | 发布/ready 有 deadline，可打断黑洞连接；worker 停机不得先等待永久发布   |
| 部署           | 独立 Gateway 与 worker               | 队列 Redis 与限流 Redis 分离；AOF、noeviction、磁盘与副本确认策略可核验 |

## 耐久与故障规则

普通 queue.add 成功不等于落盘。严格模式使用 AOF 落盘确认，校验实际确认数量；同连接关系不能被重连或客户端适配层偷偷破坏。生产必须明确已确认副本、晋升集合与故障切换策略，WAITAOF 本身不构成强一致性证明。

重复/确认丢失可重投；PG 事务保证资金效果幂等。不能只依赖 jobId：完成作业删除后相同身份仍可能再次投递，PG 保留权威去重。未知状态保留资金责任，不自动重发上游，不自动退款。

切换前需完成真实垂直路径、协议/资金回归、发布确认丢失、进程 kill/ACK 边界、Redis 黑洞、AOF 重启、worker 恢复以及完整账务压测。用户进一步确认：始终只有一套实现，不保留旧代码兼容、旧 outbox 调度器或双写开关。数据库/队列契约不兼容时明确拒绝启动，历史数据仅保留作审计，不由运行逻辑兼容。

版本恢复只能使用同一新队列契约的修订，并先确认队列与 PG 的提交状态。不提供切回旧 PG usage/outbox 入口的兼容实现。
