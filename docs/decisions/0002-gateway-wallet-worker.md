# ADR 0002：Gateway 资金预扣与 BullMQ 结算

2026-11-10 用户新增并确认，覆盖 ADR 0001 中“不在 Gateway 扣费/预扣”的约束；其余无正文持久化与逐尝试证据要求保留。

## 数据归属

业务系统：注册登录、组织商业关系、商品套餐/营销、真实支付和退款渠道。通过幂等内部 API 向 Gateway 入账；不直接写 Gateway 数据库。

Gateway：技术租户/主体授权、Key/IP、流量配额；每项目每币种独立钱包、现金与赠送额度批次、消费优先级；预扣/结算/释放/冲正、不可变账本、上游成本和客户费用的独立价格版本。绝不将供应商成本当客户售价，也不隐式换汇。

## 已确认行为

- 多币种余额独立；调用选择对应币种的价格与余额，不自动跨币种补足。
- 赠送额度支持到期和消费优先级；默认赠送优先，再现金，类内优先消耗先到期额度。可配置顺序。
- 调用上游前，PG 原子检查权限、幂等意图和可用余额，并预扣足额。可用余额不得为负；预扣分配到原资金来源。
- 成功只向客户收最终交付尝试；其他重试是 Gateway 上游成本。取消但有可信最终 usage 按实际结算。
- 缺少最终证据保留待对账预扣，不自动免收或释放。明确未执行可释放。
- 异常费用超出预扣时用可用余额补足；不足记待处理差额并冻结新调用，不能静默丢失责任。
- 释放/退款回到原币种与原现金/赠送来源；已过期赠送额度不能因释放或冲正复活。
- 金额为精确原子整数字符串；费率和预扣快照不可变；账本借贷平衡，所有外部资金命令有幂等身份与冲突校验。

## 双通道与 worker

此部分由 [ADR 0003](0003-durable-usage-queue.md) 取代。当前唯一实现为 BullMQ 白名单数字证据入口、同连接 WAITAOF 确认、worker 原子写 PG 证据和账务后 ACK。不存在旧 PG usage/outbox 路径。累计快照按物理尝试选定，不能相加。

## 性能约束

预扣前置、usage 耐久、最终扣费和恢复都进入 10,000+ RPS 验收；不关闭同步提交、不绕过余额、不取消权限检查、不把积压算完成。可使用有界微批与多实例，记录批量大小、等待上限、连接总预算及最终排空数据。共享账户热行、历史回放和队列 fanout 必须实测。

99.99% 为部署 SLO，需要依赖高可用与故障演练；代码与短时 mock 压测不能单独证明。
