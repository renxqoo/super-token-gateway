# ADR 0005：资金承诺边界与 6000 RPS 验收

2026-11-11。状态：用户已授权设计、实施及本地验证；生产故障域与真实供应商验收另行取证。继承 ADR 0002/0003 的 PG 资金权威、耐久证据、逐尝试成本和无正文持久化；本决定将正常授信纳入资金边界，取代“任何债务一律冻结”的规则。默认额度 0 保持原行为。

## 资金契约

- 金额以 10^-18 币种单位的非负原子整数字符串表示，范围为 NUMERIC(38,0)。客户费率和供应商成本分别捕获版本，精确有理数汇总后一次向上取整。
- 每项目每币种独立钱包；现金、赠额和信用分别建模，不跨币种补足。钱包 available/reserved/spent/expired 仅统计真实现金/赠额，均不能为负。授信不是充值，不创建资金批次或收入。
- 新增 `wallets.credit_limit_atoms`、`credit_reserved_atoms`、`credit_policy_version`，均默认 0；`billing_holds.credit_atoms` 表示总预扣中由信用承诺的部分。总预扣 `amount_atoms` 不改变含义。现金/赠额来源分配合计为 amount_atoms-credit_atoms。
- 正常准入必须在同一 PG 钱包锁内满足 `debt_atoms + credit_reserved_atoms + 本次信用预扣 <= credit_limit_atoms`。先按现有策略用合资格资金，再使用剩余信用。赠额到期、模型与操作限制继续有效；赠额不能清偿已有现金债务。
- `credit_reserved_atoms` 只统计 HELD/RECONCILING 的信用承诺。终态结算/明确未执行释放时恰好扣减一次；UNKNOWN、缺失维度或证据冲突保留承诺，不按时长自动释放。
- 结算优先消费该预扣的原资金来源，再按现有规则补扣合资格可用资金，剩余实际应收进入 debt_atoms；信用承诺转成实际应收，不伪造现金。退款先冲减该账单未付债务，再按原资金来源退回。
- `debt_atoms + credit_reserved_atoms > credit_limit_atoms` 时冻结，等于上限时仍可用真实可用资金调用；人工冻结和证据争议优先。异常实际应收允许突破授信并完整记录，授信约束新承诺，不截断已发生费用。余额地板始终为 0；正常信用头寸下限等价于负授信额。
- 本轮不增加结算宽限带，也不承诺客户总费用硬封顶。若未来提供硬封顶，须单独明确计价契约、平台承担差额和上游成本账务，不能静默改变现有实际计价。

## 管理及读取契约

新增私网 `POST /admin/projects/:id/wallets/:currency/credit-policy`，独立 ADMIN_KEY 授权。输入严格为 `{external_ref, expected_version, credit_limit_atoms}`，expected_version 同样为原子整数字符串。钱包须已存在，可通过现有正金额入账建立；币种与项目来自路径。

钱包锁内先按 wallet_id/external_ref 查询持久化指纹，相同身份与载荷返回原命令标识及版本，不重新应用；载荷不同、版本过期或新额度小于已有债务及信用承诺均返回 409/billing_conflict。合法更新提高策略版本，并写不可变命令记录；不改动余额或 money_journal。404 表示钱包不存在，422 表示非法值，依赖故障返回 503/现有清洗错误协议。人工冻结继续使用原 PATCH，不受调低额度冲突阻碍。

钱包查询新增授信额度、在途信用、剩余信用、超限金额与策略版本，均为字符串；账单查询新增该请求信用预扣。剩余信用为 max(0,limit-debt-credit_reserved)，不是不受模型限制的总可支配余额。

资金变更、结算、收债、退款、对账和人工冻结统一按新敞口计算冻结状态。信用政策由安全定义函数写入，运行角色不能直接改额度、信用预扣及政策记录。命令重放身份长期保留。

## 原子边界和迁移

预扣事务同时处理授权、幂等意图、钱包锁、合资格资金分配、信用占用、HOLD 和首次 attempt。结算继续由 persist_usage_batch → settle_requests 在同一 PG 事务提交证据、账单及平衡流水，提交后 ACK。纯现金快速结算只接受 credit_atoms=0，信用走完整结算。

schema10 及已有支持的 schema06–09 显式停机升级到 schema2026111101：停止生产者和 worker、排空并核对队列、备份、断开客户端，执行既有 `db:migrate -- --upgrade --quiesced`。新增字段为 0，旧资金与开放预扣不变，旧欠费继续冻结。应用启动只接受当前 schema；运行中没有兼容分支。升级事务失败回滚，写入信用业务后不能靠旧应用回退。

验收包含：现金100/授信50/三笔各60并发只准两笔；信用待对账不释放；重复结算不重复转债；释放/退款/现金偿债恢复额度；赠额不还旧债；多币种隔离；同策略命令并发重放；旧命令重放不覆盖新版本；并发调额和预扣；超额结算冻结及恢复；最小权限；schema10 存量升级。

## 架构及演进

保留模块化代码、独立 Gateway/worker、PG 钱包锁、分片准入 Redis 和独立证据 Redis。先隔离资源并定位 CPU、锁、WAL、Redis 和负载发生器瓶颈，再决定分片。单钱包的严格资金承诺仍有串行点；不为扩容把真实余额搬进缓存。项目分片和持久化资金子额度仅在瓶颈证据支持后设计实施。

6000 RPS 的正式口径、持续验收和对标见 [容量契约](../performance/capacity-contract.md)。对标使用本机 work/Tillgate 与 work/new-api，记录 HEAD、工作区差异、配置、语义和原始证据。商业支付与控制台继续在 Gateway 边界之外；协议差距单列，不能用不支持的操作获得性能优势。

## 实施结果

资金与验收装置已落地，77单元、260真实集成、8项产物及8项原生耐久检查通过；6000 RPS和低速两分钟实测均未通过，60分钟磁盘预检拒绝。详见[实施与复验](../performance/funds-capacity-2026-11-11.md)，不将设计目标写成完成结果。
