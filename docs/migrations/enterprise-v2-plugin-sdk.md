# T04.a plugin execution slice

This slice implements the Bun supervisor, restricted ABI v1, SDK, immutable package reader and an OpenAI Chat WASM adapter with a pinned source build entry. It depends on the accepted T02.a runner and T03 contracts. The authoritative decisions remain in `enterprise-v2.md` in the coordinating workspace. Gateway/Core assembly, admissions, network transport, credentials, durable terminal release and package publication remain T04.b/c and T08.

The approved deterministic builder fixes only the compiler's Wizer preinitialization random/clock imports through its supported Linker entry. The official engine bytes and native runtime are unchanged. Each actual Chat and isolation build is repeated twice in one directory and once in another, and all three hashes must match before the checked-in artifacts are replaced. The original official-compiler nondeterminism failure and samples remain evidence. Signed package digest immutability is mandatory independently of source-to-bytes reproducibility. This component candidate still requires coordinating integration and independent review.

The supervisor launches the runner in an owned Unix process group with a numeric-only environment. It continuously reads bounded JSONL frames, limits pending commands and bytes, bounds writes, monitors heartbeat, settles all commands on failure and kills the complete group before waiting. JSONL limits apply to each complete line, including its LF delimiter, and the incomplete suffix independently of stdout chunking. Reads are capped at one frame budget; retained suffix bytes are copied without retaining a larger transport chunk, and a joined line is checked before allocation. A valid complete reply can settle before a later oversized suffix retires the helper. Restart has a lifetime limit and never replays a failed call. Compiled WASM is the only native reusable object. No guest or session is retained in a native slot.

ABI input contains version, hook, immutable config, host-created session identity and batch sequence, and base64 payload. Hooks are describe, prepare, response, error, stream_open/feed/drain/finish/dispose, resource_prepare/response and balance_prepare/parse. Unsupported hooks fail explicitly. State travels as opaque JSON source bytes through native IPC. The Bun attempt registry exclusively chooses the state for the next batch and atomically replaces it after validating output. A failed batch disposes the attempt. Concurrent calls on one session, late calls and expired attempts fail. Every attempt has independent total deadline and state/output budgets, plus a global state budget. Concurrent cold loads share compilation but retain independent waiters: cancellation or the attempt deadline releases that caller immediately without cancelling another caller. The last departing waiter cancels the underlying load through the existing acknowledgement and target-completion protocol. Pre-aborted loads do not start a helper; failed or abandoned loads are removed from the cache, and no waiter signal listener survives settlement.

Failure codes are an SDK-defined enum, with no guest-selected message or stack. A stream failure can carry only the last already-validated numeric usage/finality snapshot; fields from the failing frame cannot establish or replace it. The failure ABI permits these optional facts for later durable evidence, without creating a terminal candidate or promoting finality. Invalid JSON/schema output becomes safe `ABI_INVALID`; guest keys, diagnostic text or arbitrary codes cannot become outward errors. A plugin error or HTTP-like status never establishes NOT_EXECUTED or releases a hold. The future transport owner must preserve physical-attempt responsibility independently.

The coordinating specification also requires a unified SSE frame/data/document path after the prototype rejected a valid 70,067-byte event. The host handles only standard UTF-8/CR/LF/CRLF/SSE field syntax and bounded opaque buffers; the guest chooses every protocol inspection, string accumulation, JSON edit, output/hold and terminal candidate. The existing 1,048,576 normalized line-byte event limit remains, with separate raw-wire, partial-frame, ready-frame, held-output and aggregate memory budgets. No complete large event enters guest/IPC. Tool argument fragments use owner-bound bounded string buffers and generic JSON checks requested by the guest. Frame/data references expire after consumption; only explicit string-buffer references can span frames within the same attempt. All cancellation/disposal paths release both kinds.

Prepare returns a relative request path, method, safe headers, body, bounded auth descriptor and numeric-only billing manifest. Authentication injection and final permit binding belong to the future transport host. A terminal is a separate candidate; stream finish cannot invent a candidate at EOF. No SDK API releases a normal terminal to a client.

The coordinating specification now authorizes immutable JSON body handles for every JSON request/response size. Real TS-PDK measurements found 2 MiB bodies trap while encoding under the fixed 64 MiB guest limit, even after replacing JavaScript base64 loops with the pinned PDK's native Rust codec. The raw 16 MiB public request limit remains. The guest requests at most four rounds of sixteen JSON pointers, receives bounded exact node facts, and returns at most 32 nonoverlapping set/remove operations with at most 64 KiB total replacement data. The host implements only generic strict JSON indexing, immutable snapshot inspection and byte-slice materialization. It contains no Chat field selection or protocol mapping. Handles and index/output copies consume an independent aggregate budget and expire with the attempt. Final JSON has an independent bounded allowance for small legitimate additions, and a host-computed digest before later admissions. Unknown, cross-session/document, stale and cancelled handles fail; duplicate, ancestor-overlapping and ambiguous plans fail rather than applying sequential array shifts.

Packages are uncompressed, strictly validated file maps with a signed canonical digest. The digest covers a domain prefix and each UTF-8 path and byte length in sorted order, followed by file bytes. Duplicate/unsafe paths, unknown envelope or manifest fields, missing provenance/license/schema/fixtures, oversized files and unknown ABI/capabilities fail. Trust anchors are required; there is no unsigned production path. Core upload/validation/publication remains T08.

The built-in Chat adapter preserves same-protocol fields and exact JSON number literals, maps the model and enforces a final output token ceiling. It supports bounded JSON and incremental SSE, arbitrary UTF-8 boundaries, tool deltas, cumulative usage and finality. Unrepresentable protocol/operation semantics return 422. Usage numeric errors return 502. Usage-less valid responses are UNKNOWN. An incomplete numeric snapshot is PARTIAL; stream snapshots remain PARTIAL until a valid terminal. Truncation, empty content, malformed/error frames and absent normal terminal never become successful EOF. All transformations execute the checked-in WASM via the same ABI.

The existing connectors and tests remain in place for T09. Their exact-number and terminal behavior is the evidence baseline; this slice adds independent synthetic golden vectors at the new public boundary. Tests do not download tools or access PostgreSQL, Redis, real environment files or suppliers. Bun-based synthetic IPC helpers start with `--no-env-file` so their inherited working directory cannot add dotenv keys to the supervisor's numeric-only environment. The unknown/duplicate-reply regression runs from a temporary directory containing a non-secret `.env.local` sentinel and still requires exactly `GOMEMLIMIT` and `GOMAXPROCS` from consecutive stats replies; the original working directory, helper process and temporary fixture directory are restored or removed in cleanup. macOS process tests do not establish Linux cgroup enforcement or full Gateway capacity.

## Consumer API

Import `verifyPackage`, `createPluginSupervisor`, `createPluginAttempts` and the ABI types from `@gateway/plugin-host`. The built standalone facade exports the same SDK verifier so verified package identity and its private immutable snapshot belong to one module instance. `@gateway/plugin-sdk` is also available to source consumers and guest builders. Do not transfer a JavaScript verified object between independently bundled verifier instances; transfer signed package bytes and verify at the receiving boundary.

`verifyPackage(bytes, trust)` requires a nonempty matching Ed25519 public trust anchor. It returns a branded verified package and retains a private immutable snapshot; mutating its public inspection view cannot substitute executable bytes, config schema or manifest. `openAIChatPackageFiles()` returns unsigned immutable-package inputs for publication or explicit synthetic test signing. It grants no trust. Core publication is not implemented here.

`createPluginSupervisor({ executable, native, ...limits })` owns one native process group. `load` and `call` are low-level transform primitives, not a publication authorization API. Application consumers use `createPluginAttempts(supervisor, limits).create(pkg, options)`. Options bind tenant, physical attempt, incarnation, validated ordinary config and absolute total deadline. Secret references belong to the future external binding and never enter ordinary config or guest input. Descriptor `auth` selects only `none`, `bearer` or the bounded `api-key` template; it has no credential value or signing function.

`attempt.transformJSON(hook, metadata, rawBytes, signal)` is the only JSON path for `prepare`, `response` and `error`. Prepare metadata is `{ protocol: "chat", operation: "chat", model }`; response metadata is `{ model }`. The result is `{ result, body?, bodyDigest? }`. `result.kind === "prepared"` exposes the relative path, method, safe headers, auth descriptor and numeric manifest; `body` is the separately materialized final request and `bodyDigest` its SHA-256. The request's ABI `body` field is a consumed body-plan descriptor, not transport bytes. Response returns the materialized body separately with `chunks: []` and a terminal candidate. Numbers in the original document never pass through Number. Guest scalar facts use raw JSON literal strings; original prompt/media bytes never enter a Core payload through this API.

Final request bodies allow at most 16 MiB + 64 KiB, with at most 64 KiB growth over the original snapshot. Callers must validate final policy and bind/check the final body and canonical header digests before later admissions/send. Config `max_input_tokens` is an explicit reservation ceiling; this component does not provide a tokenizer or certify a provider's maximum context. The Chat adapter also rejects a raw request larger than that configured ceiling in bytes. `max_output_tokens` bounds final `max_tokens`/`max_completion_tokens`. Conflicting ceilings, multiple choices or other protocol/operation conversions return explicit 422 rather than weakening semantics.

Streaming uses `invoke("stream_open", UTF8(JSON.stringify({ model })))`, then immediate finite `stream_feed` byte batches (default at most 128 KiB). Feed returns an exact consumed prefix, base64 output chunks, numeric snapshots, `needs_input` and an optional terminal candidate. Retry any unconsumed suffix after draining. While `needs_input === false` and there is no terminal, call `stream_drain` with no input. Each public operation executes at most 32 guest control calls and emits at most 128 already-ready frames; it returns promptly with remaining work for the next drain. It never waits for a batch to fill. All normal output is preserved across the public drain loop.

Each output batch with retained wire has a host-generated `output_id`; call `attempt.releaseOutput(output_id)` after the bounded transport write completes or fails. The owner retains and charges the batch until release or disposal. A candidate contains the withheld finish/usage/sentinel wire and is subject to the same lease. `stream_finish` validates a completed stream; EOF without valid finish/content/sentinel fails. Successful finish clears string buffers and guest state but retains the finite-deadline attempt and outstanding output leases for the later durable fence and delivery. Always dispose in a caller `finally`. Dispose is unconditional and idempotent.

Standard SSE framing applies to every event size. `maxEventBytes` defaults to 1,048,576 normalized UTF-8 line bytes plus one per line, including the empty event delimiter. Raw CRLF wire has its own twice-event bound; ready wire defaults to 256 frames / 8 MiB, and held candidate wire to 256 frames / 8 MiB. Frame syntax, JSON indexes, rendered output and leases share the aggregate JSON ledger. Frame/data/document handles expire on consumption; guest-selected references never choose another owner or epoch. JSON facts preserve raw literals and can expose bounded string length plus a SHA-256 over UTF-16LE code units, allowing opaque string identity checks without copying large identifiers into a guest.

The guest requests bounded string append/check operations from the current frame JSON string pointers. At most 128 owner-bound accumulators and 65,536 append operations are allowed. Their combined decoded UTF-8 fragment budget is 1,048,576 bytes; each fragment is charged independently. Stored JavaScript UTF-16 strings are concatenated before UTF-8 encoding, preserving a surrogate pair split across fragments while still charging the legacy 3 + 3 fragment bytes. String parts, map/token metadata, Unicode copies and JSON validation indexes all consume the global ledger. Repeated append pointers in a frame, stale or foreign buffers, append followed by trap/cancel, malformed final JSON and budget exhaustion close the owner. The host performs no Chat/tool/finality interpretation.

Keep the attempt alive through the later durable fence and transport delivery, then call `attempt.dispose()`. This releases retained state and JSON output leases, invalidates all document epochs and aborts in-flight pure transforms. JSON success does not auto-dispose before the caller can finish delivery. Attempt failure, cancellation or deadline disposes immediately. Call the registry's `dispose()` when a shared supervisor remains in use; it releases every attempt and disconnect subscription without stopping that supervisor. `runPluginFixtures` always disposes its temporary registry, including on fixture failure. Close the attempts owner at service shutdown; `close()` disposes the registry and closes its supervisor. A helper retirement immediately invalidates all owners bound to that connection, including idle accumulated streams. A later helper restart serves only future attempts and never repeats a failed call or authorizes a network send.

## Enforced component budgets

Native defaults and ranges remain [the accepted runner contract](../../packages/plugin-host/native/README.md). In addition, Bun defaults to 32 pending commands / 64 MiB serialized pending frames / 16 MiB queued writes / 12 MiB read frame, a 1s queue deadline, 3s heartbeat loss deadline, 2s close deadline and at most two lifetime restarts. Execution admission uses the native slot count with native queue zero; queued calls have their own deadline before dispatch. Native `callMs` and `compileMs`, transport write deadline and total attempt deadline remain independent. Four reserved control slots cannot make the execution queue unbounded.

The attempt registry defaults to 128 attempts, 256 KiB state per attempt, 16 MiB aggregate retained plus in-flight reserved state, 128 KiB control input/output batches and 64 MiB total output per attempt. Bun code-module references have a four-module / 32 MiB bound; the native compiled cache has its separate immutable-module budget. Module eviction can require a future pure transform to load again; failed calls are not replayed. JSON feed bodies have their independent 16 MiB raw limit.

The JSON ledger defaults to 256 MiB. Each document has depth at most 64 and at most 100,000 total nodes, including array elements, with 1,024 reserved bytes per index node plus raw/copy and decoded-key allowances. Flat arrays consume the same node and aggregate limits as objects. It reserves raw/copy/validation/output allowances before allocation and charges key/index nodes conservatively, including a second validation index. Original and final bytes, node indexes, bounded replacements and output leases are included. This is a component-owned byte ledger, not a hard RSS or Linux cgroup guarantee. Returned body buffers belong to the caller's bounded transport lifecycle; the component retains and accounts their lease until attempt disposal. Document UUID, private owner binding, session batch sequence and consumed epoch prevent guest-selected lookups across document, tenant, attempt or incarnation. Plans use original offsets, reject duplicate/ancestor overlap and reject ambiguous structural changes.

## Package and build provenance

Wire package format is strict uncompressed JSON `{ format: 1, files: [{ path, data: base64 }], signature: { algorithm: "Ed25519", key_id, value: base64 } }`. Decoded contents total at most 32 MiB; at most 128 files, nesting at most four path segments, module at most 8 MiB and fixture files together at most 2 MiB. Metadata files are at most 256 KiB each. Wire JSON is separately capped at 44 MiB. Absolute/empty/dot paths, backslashes, duplicates, unknown envelope/manifest fields and unsupported ABI/operation/dimension fail. Required files are `manifest.json`, `module.wasm`, `config.schema.json`, `fixtures/cases.json`, `LICENSE` and `provenance.json`. The config schema uses the implemented bounded object/string/integer/boolean/map subset; it is not an unrestricted executable schema engine.

The digest is SHA-256 of UTF-8 `gateway-plugin-package-v1\0`, then files sorted by path using lexical ordering. Each file contributes ASCII decimal `utf8_path_length:path:byte_length:` followed by exact file bytes. The signature covers the 32 decoded digest bytes. No file, even an optional license or source-hash file, is outside the digest. Expected package digests and release trust belong to Core T08; no built-in replacement is automatically trusted.

Fixture suites use strict format 1 with a validated ordinary synthetic config and named step sequences. Steps are bounded hook input, immutable JSON transform with expected body, or cancellation. Expectations are independent golden business fields; full materialized body bytes are compared where supplied. `runPluginFixtures(supervisor, pkg)` executes all steps through the actual host/guest path and returns only counts and cleanup statistics. Its checks do not replace T08's lease, publication, security and admission lifecycle.

`bun run setup:plugin-tools --fetch-tools --fetch-dependencies --rust-bin /absolute/rust/1.95.0/bin` explicitly acquires the hash-pinned official archives and compiler source in `scripts/plugin-tools.json`, verifies the original and patched Cargo locks, applies the checked-in minimal preinitialization patch, extracts and hashes the exact original engine section, and performs a frozen two-job local source build. Rust 1.95.0 is required; this command installs nothing globally. Setup is bounded to 15 minutes, 8 GiB total cache, 8 MiB logs and at least 4 GiB free disk. For an independently approved local compiler, `setup:plugin-tools --import-tool /absolute/extism-js` accepts only the pinned reference CLI hash and writes a verified receipt. Ordinary tests never fetch or build toolchains.

`bun run build:plugins` uses only the verified local receipt and `.local/plugin-tools` cache. An explicit `--fetch-tools` may acquire the two pinned upstream tool archives; it does not replace the deterministic compiler setup. The builder verifies esbuild 0.28.2, lossless-json 4.3.3, official PDK v1.7.0 archive hash and self-reported 1.6.1, Binaryen 133, the deterministic patch/locks/compiler and extracted engine hash. Relative compiler filenames avoid workspace absolute paths. The mandatory two-same-directory plus one-relocated reproducibility assertion runs for both actual Chat and isolation artifacts on every build. Checked-in artifacts include original TS, declarations, source hashes, tool/patch provenance and third-party notices. Unit gates reject stale sources/provenance.

The approved CLI was source-built and the actual WASM matrix was verified on macOS arm64. The bundled engine was extracted unchanged from the official CLI and was not rebuilt from source. Reproducibility of the CLI binary itself and cross-platform WASM output were not measured. Linux runtime/service enforcement and a Linux builder matrix remain T14.

`bun run build:native` uses Go 1.27.4, local module/build caches and reproducible `-trimpath -buildvcs=false`; its explicit build phase can acquire the checksum-pinned Go dependencies. `bun run test:native` performs read-only gofmt, vet and explicit `go test ./__test__` using that cache with module/network lookup disabled; `test:native:race` is the full race entry. Root `test`, `build` and `verify` include native prerequisites and the new Bun packages. `test:plugin-artifact` copies only the built native/library/package artifacts into an isolated temporary directory, verifies an explicit ephemeral synthetic signature, executes every fixture without node_modules or network and waits/reaps owned processes. PostgreSQL/Redis/Gateway artifact and durability checks remain separate and were not run by this slice.
