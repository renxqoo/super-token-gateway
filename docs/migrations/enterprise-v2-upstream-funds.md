# enterprise-v2 T06 上游资金管理面

上游充值、凭证登记、供应 hold、超预估冻结与共享账户并发硬闸已在 T04.b.funding/T04.b.2 落地并有 v2 用例（`core-management.test.ts`、`core-settlement*.test.ts`、`core-supplier-exposure.test.ts`、`upstream-funds.test.ts`）。T06 补齐 [§5.3](enterprise-v2.md) 中尚缺的管理面，使账户冻结后能经人工调账/对账审计恢复。

## 1. 决策

- **D1 权限**：新增平台权限 `funding:adjust`（追加迁移 `2026111214` 替换 `core_platform_authorize_v1` 权限枚举），用于调账、人工对账及账户启停；品牌与账户的创建、品牌启停沿用 `catalog:manage`；所有读取用 `funding:read`；充值与凭证上传仍为 `funding:recharge`。
- **D2 账户状态**：PATCH 只允许 `ACTIVE`↔`DISABLED`。`RECONCILE_REQUIRED` 只能由带 `resume: true` 的人工对账恢复；`QUARANTINED` 不经本接口解除。普通充值或正向调账都不复活账户。
- **D3 调账**：带符号 atoms，按 `(account, ADJUSTMENT, external_ref)` 与业务载荷摘要幂等；要求 `expected_revision` 等于该币种余额当前 revision（准入、结算、充值都会推进该 revision）；平衡流水 `upstream:available` ±delta / `external:adjustment` ∓delta；凭证可选，但 id 与摘要必须成对。调账后余额低于该币种预留时，ACTIVE 账户立即转 `RECONCILE_REQUIRED`，停止新 grant。
- **D4 对账**：每个 `(account, currency, balance revision)` 只有一条记录，同 revision 同内容重放返回原记录（200），内容不同 409。差额 = 账单（无则观测值）− 账面，不改余额。`resume: true` 要求账户为 `RECONCILE_REQUIRED` 且所有币种余额 ≥ 预留，再置 ACTIVE。
- **D5 查询**：`holds`、`journal` 支持 `currency`、`channel_id` 过滤与 `before` keyset（每页 100）；`GET .../recharges` 返回充值回执列表。
- **D6 凭证读取**：沿用 T04 已有上传路径，读取为 `GET /admin/financial-vouchers/{id}`（规格写作 `/admin/vouchers`，为同一资源不分叉路径），`funding:read`，以 `attachment`、`nosniff`、`no-store` 输出原始字节。
- **D7 暂缓与归属**：`.../reports`（展示/报表）按 2026-11-14 用户裁决暂缓；`.../balance-observations` 依赖插件能力声明，归 T08。OpenAPI 与其他 Core 管理路径一样在 T14 统一。
