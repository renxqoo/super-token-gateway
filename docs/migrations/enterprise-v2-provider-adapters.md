# enterprise-v2 T09 文本与云适配迁移

## 1. 当前行为（代码核对）

- v2 Gateway 只公开 `POST /v1/chat/completions`，唯一插件 `gateway.openai-chat` 直连 OpenAI 兼容上游；其余 provider kind（anthropic/gemini/deepseek/ollama/azure/bedrock/vertex）与入站协议 responses/messages/gemini 仍由 legacy gateway 经 `packages/connectors` 的 TS 转换执行。
- ABI v1 body plan 只有 `set`/`remove`（≤32 条、单值 ≤4KiB、合计 ≤64KiB），guest 不读取正文；因此无法表达需要搬移用户内容的协议转换（chat→messages 的 system 提取、tool_calls→tool_use、参数字符串→对象）。
- inspection 每轮 ≤16 个精确指针、≤4 轮；无法在一轮内获得 N 条消息的角色/内容类型。
- 宿主认证只有 none/bearer/api-key；`packages/runtime/src/cloud-auth.ts` 已有 SigV4 签名与 Vertex OAuth token 刷新，但只被 legacy 使用。SSE 之外无二进制流 codec。
- 插件构建工具链（确定性 extism-js）需本地 Rust 1.95.0 源码构建；本机已在 `.local/` 内完成并复现出与提交一致的 `module.wasm`。

## 2. 决策

- **E1 组合计划（ABI v1 增量能力）**：body plan 增加互斥形态 `compose`：`{document, compose: {template, slots}}`。`template` 为 guest 生成的严格 JSON（≤256KiB）；`slots`（≤4096）把模板中的 `null` 叶子替换为源文档内容：`value` 原样字节、`parse` 将源 JSON 字符串解析为值（同一严格索引与深度/字段/数值限制，失败为 `invalid_json`：prepare 400，response/stream 502）、`stringify` 把源节点原文作为 JSON 字符串、`concat` 把 ≤256 个源字符串按 Unicode 拼接为一个字符串。宿主只做通用复制/解析/序列化/拼接，不识别协议字段；输出 ≤ 源文档 + 模板 + 64KiB，并复用同一最终索引、摘要与预算。request、response 与 frame 的 body 都可使用 compose。
- **E2 通配 inspection**：指针段 `*` 在数组展开为各下标、在对象展开为各成员键（`*` 因此成为保留段，不能按字面键查询），单轮展开后 ≤4096 个事实，事实 JSON 上限由 128KiB 调为 256KiB。轮数上限保持 4。guest 借此枚举顶层字段，对未声明字段显式拒绝而不是静默丢弃。
- **E3 帧计划**：frame plan 增加 `disposition: "drop"`（消费帧且无输出，不能带 body/extra，不能作为终态）、`data_only: true`（渲染时去掉 event/id/comment 行）与 `extra`（≤4 个 guest 生成的、各 ≤4KiB 且不含 CR/LF/NUL 的字面 data 事件，追加在该帧之后，如 `[DONE]`）。它们是通用 SSE 组合能力，不带协议分支。
- **E4 云认证**：长期云凭据只留在 Core，不进入 Gateway 与 guest。
  - `google-oauth`：插件声明 `{type: "google-oauth"}`，绑定配置 `auth` 必须同值。渠道密文为 base64url 编码的 JSON（服务账号 `{type: "service_account", client_email, private_key}` 或预签发 `{access_token, expires_at}`），编码后仍满足渠道密文“可打印无空格、≤4096 字节”的现有约束。Core 在签发 transient send 时用 `packages/runtime` 的 `VertexTokens` 换取或校验访问令牌（缓存、提前 60 秒刷新、令牌端点固定 `https://oauth2.googleapis.com/token`），以 `bearer` 材料下发给 Gateway；密文格式错误、预签发令牌过期或换取失败时 Core 不签发 transient send，Gateway 以 attempt `NOT_EXECUTED`/`send_not_authorized` 记录、不发送上游、不计费并返回 503 `core_unavailable`。
  - `aws-sigv4`（j5）：插件声明 `{type: "aws-sigv4", service: "bedrock"}`，绑定配置 `auth` 同值。渠道密文为紧凑 JSON `{accessKeyId, secretAccessKey, region, sessionToken?}`（与 legacy 相同，`awsCredentials` 校验）。Core 签发 transient send 时生成 `amz_date`（当前 UTC 秒）并派生当日 `kSigning = HMAC(HMAC(HMAC(HMAC("AWS4"+secret, day), region), service), "aws4_request")`，下发 `{type: "aws-sigv4", access_key_id, session_token?, region, service, amz_date, signing_key}`；secret access key 不离开 Core。Gateway 在最终 URL、请求头与请求体字节上用 `packages/runtime` 的同一 SigV4 规范化实现签名（签入 host、x-amz-date、x-amz-content-sha256、可选 x-amz-security-token 及插件声明的请求头）。派生密钥只对该日期/区域/服务有效，grant 有效期 ≤30 秒。
- **E6a 同协议入站（j6a）**：Gateway 新增 `POST /v1/messages`、`POST /v1/responses`、`POST /v1beta/models/{model}:generateContent|streamGenerateContent`（Gemini 的 model 与 stream 取自路径；密钥接受 `Authorization: Bearer`、`x-api-key`、`x-goog-api-key`）。operation 等于入站协议，Core context/tariff/路由按该 operation 选择；prepare 元数据 `protocol=operation=<入站协议>`，response 元数据与 `stream_open` 负载携带 `protocol`，插件据此输出入站协议格式。Core 候选已按 Key/模型/路由/价格的 operation 与插件 manifest `capabilities.operations` 过滤，插件须同时声明该 operation 与 protocol；无候选与 chat 相同为 503 `no_route`。同协议插件只做模型映射、输出上限、用量计量与终态保留，其余字段与帧原样透传（响应/帧中的上游模型名改写为逻辑模型名）。依赖资源状态的 Responses 特性（`previous_response_id`、`background: true`）在 T11 资源迁移前 422；客户端 `anthropic-beta` 头不透传（插件看不到客户端请求头），与 legacy 不同。错误响应沿用 Gateway 现有 OpenAI 风格结构（legacy 亦同）。Anthropic Messages 与 Bedrock 插件在 j6a 声明 `messages`，发行升为 `gateway.anthropic-messages-1.2.0` 与 `gateway.bedrock-anthropic-1.1.0`；Bedrock 原生入站移除 `model`/`stream` 并写入 `anthropic_version`，客户端自带 `anthropic_version` 时 422。
- **E6b 跨协议入站（j6b）**：协议转换与上游无关，由 Gateway 宿主而非每个插件实现：插件未声明入站协议 X、但声明 `chat` 时，Gateway 用 `@gateway/adapters/protocol`（j6b 由 `packages/connectors` 原样迁入，legacy 同步改用该路径，旧包删除且不留别名）的 `decodeRequest(X)`→`encodeRequest(chat)` 把请求转为 chat 交给插件的 chat 路径，再把插件输出的 chat JSON 经 `decodeResponse(chat)`→`encodeResponse(X)`、chat SSE 经 `StreamTranslator(chat→X)` 还原为 X 格式；与 legacy 的 `prepareRequest`/流转换使用同一实现，转换不能保留的字段为 422 `conversion_loss`（legacy 同）。计费与授权仍按入站 operation X：Core 候选条件改为插件声明 X 或（X 为 chat/responses/messages/gemini 之一且插件声明 `chat`），Key/模型/路由/价格仍按 X 过滤；Gateway 对转换路径以元数据 `protocol=operation=chat` 调用插件既有 chat 路径（插件不改、不升版），校验插件 manifest operation 为 `chat`（原生路径须等于 X）后由 Gateway 在 billable manifest 与派发投影中写入入站 operation X；Core 迁移 2026111217 以 `CREATE OR REPLACE` 更新 `core_candidates_v1`，继续校验 manifest operation 等于 context operation。插件计量不变（输出的是 chat 用量），Gateway 只做格式还原，不重新计量。同时声明 X 的插件始终走原生路径。
- **E6c Gemini 模型列表与入口切换（j7a）**：`GET /v1beta/models` 与 `/v1/models` 同在 Core 公开监听（账户鉴权、IP 与 Key 模型范围相同），返回 legacy 同形 `{models:[{name:"models/<模型>", supportedGenerationMethods:["generateContent","streamGenerateContent"]}]}`，只列 operations 含 `gemini` 的模型。`infra/Caddyfile` 把 `POST /v1/messages` 与 `/v1beta/models/*`（生成路径）转到 v2 Gateway、`/v1beta/models` 转到 Core 公开监听；`/v1/responses` 仍走 legacy，直到 T11 迁移 `previous_response_id`/`background` 与资源检索（Caddy 不能按请求体分流）。
- **E6d 原生文本操作与字符计量（j7b，C03）**：Gateway 新增 `POST /v1/embeddings`、`/v1/moderations`、`/v1/completions`（Caddy 同转 v2），operation 即路径操作，prepare/response 元数据只带 `operation` 与 `model`（无 protocol，不做协议转换）。`gateway.openai-chat` 升为 1.3.0 并声明这三种 operation：请求只改写 `model`，`stream: true` 422（legacy 同样不允许这三种流式）；completions 的 `max_tokens` 缺省写入配置上限、超限 422，embeddings/moderations 只给 input_tokens 与 requests 上限；路径 `/v1/<operation>`，azure path_style 为 `/openai/deployments/<部署>/<operation>?api-version=…`。响应只改写 `model`：embeddings 须 `object:"list"` 且 `data` 为数组，用量取 `prompt_tokens`、输出记 0；moderations 须 `results` 为数组，上游不返回 token 用量，以 `requests:1` 作为 FINAL 用量；completions 须单个 choice 与合法 finish_reason，用量同 chat。字符计量：Gateway 对所有操作以共享 `requestCharacters`（legacy 同一实现）按入站请求体计算字符数写入 billable manifest `input_characters`（无法计数时省略，INPUT_CHARACTERS 价格因此拒绝，与 legacy 同）；此前 v2 未填该字段，INPUT_CHARACTERS 价格在 v2 无法报价。
- **E7 二进制流 codec**：manifest `stream_codec` 增加 `aws-eventstream`：宿主按 AWS event stream 编码解帧（prelude/消息 CRC32、长度 ≤ `maxEventBytes`、头部仅字符串类型且不重复），只接受 `:message-type=event` 且 `:event-type=chunk`，载荷须为 `{"bytes": <标准 base64>}`，解码后的 UTF-8 JSON 作为一个 SSE 事件（`event` 取内部 `type` 字符串，`data` 为解码字节）交给同一 SSE 帧计划流程；异常消息、CRC/长度错误或 EOF 时残留字节均为 502 `invalid_stream`/`stream_truncated`。codec 是传输解封装，不解释 Anthropic 语义。
- **E5 内置包集合**：bundled release 从单一 `gateway.openai-chat-1.0.0` 扩展为显式内置集合，每个 release 仍受部署 policy `releases` 列表及 key `release_ids` 约束。
- **E6 入站协议**：`/v1/responses`、`/v1/messages`、Gemini 路径在 v2 Gateway 以同一 ABI 执行，插件声明支持的入站协议；未声明组合在候选准备阶段排除。

## 4. 实施记录

- **j1 组合能力**：`packages/plugin-host/src/json-documents.ts` 实现 compose（value/parse/stringify/concat）与 `*` 通配展开；`attempts.ts`/`sse-stream.ts` 把 compose 源解析失败映射为 `invalid_json`（prepare 400，其余 502）；`sse-stream.ts` 实现 `drop`、`data_only` 与 `extra`；`packages/plugin-sdk/src/abi.ts` 增加对应 schema。旧 `edits` 计划、openai-chat 包字节与行为不变（本机源码构建的确定性 builder 重建出与提交一致的 `module.wasm`）。
- **j2 Anthropic**：`packages/adapters/anthropic-messages`（`gateway.anthropic-messages-1.0.0`）。chat→messages：system/developer 提升为 `system` 文本块；user 文本与 http(s) 图片 URL；assistant 文本与 `tool_calls`→`tool_use`（空参数为 `{}`，参数串经 compose `parse`，非法为 400）；`tool`→`tool_result`；tools/tool_choice/parallel_tool_calls/stop/temperature/top_p/user 映射；`x-api-key` 与 `anthropic-version: 2023-06-01`。顶层与消息字段按白名单枚举，未声明字段、data URI 图片、`name`、strict 工具、`n>1` 均显式 422。响应与 SSE 转为 chat completion / chunk：多段文本 `concat`、`tool_use.input` `stringify`、stop_reason 与 legacy 相同映射、缓存用量拆为 `cached_input_tokens`/`cache_write_tokens`；SSE 丢弃 ping 与块边界帧，finish 帧与 usage 帧连同 `[DONE]` 作为终态候选保留到耐久屏障之后。
- **E5 内置集合**：`bundledReleaseIds` = openai-chat 与 anthropic-messages；policy `release_ids`/`releases` 接受集合内 ID，Core 校验按 release 选择对应仓库内置文件；`plugins:sign-bundled` 增加必填 `--release-id`。
- **j3 OpenAI 兼容族**：不新建插件，`gateway.openai-chat` 升为 1.1.0 并增加配置：`path_style: "azure"` + `api_version`（`YYYY-MM-DD[-preview]`，guest 校验）发往 `/openai/deployments/<upstream_model>/chat/completions?api-version=…`，部署名限 `[A-Za-z0-9._-]{1,64}`；配合 `auth: "api-key"`（`api-key` 头）。`output_field: "max_tokens"` 以 `max_tokens` 下发输出上限并把客户端 `max_completion_tokens` 改名，供 Ollama 等旧兼容端。DeepSeek 直接用默认配置（bearer，`/v1/chat/completions`），`prompt_cache_hit_tokens`/`prompt_cache_miss_tokens` 用量 1.0.0 已支持；Ollama 用 `auth: "none"`。legacy 的 Azure `apiVersion` 存于密文 JSON，v2 改为非秘密的绑定配置，密文只放 key。
- **j4b Vertex**：`gateway.gemini-generate` 升为 1.1.0：`path_style: "vertex"` + `project`（`[a-z][a-z0-9-]{4,61}[a-z0-9]`）与 `location`（`[a-z0-9-]{1,40}`，guest 校验）发往 `/v1/projects/<project>/locations/<location>/publishers/google/models/<upstream_model>:generateContent`（流式 `:streamGenerateContent?alt=sse`），渠道 base_url 为区域端点。ABI auth 与 Core `dispatchAuthSchema` 增加 `google-oauth`；Core 按 E4 换取令牌后以 bearer 下发。
- **j4a Gemini**：`packages/adapters/gemini-generate`（`gateway.gemini-generate-1.0.0`），发往 `/v1beta/models/<upstream_model>:generateContent` 或 `:streamGenerateContent?alt=sse`，`auth: "api-key"` 使用 `x-goog-api-key`（ABI 与 Core 契约的 api-key 头枚举增加该值）。前缀 system/developer 合并为 `systemInstruction`，非前缀 system 422（同 legacy）；assistant `tool_calls`→`functionCall`（含 id，参数经 compose `parse`），连续 `tool` 消息按 `tool_call_id` 回查函数名并合并为一个 user 回合的 `functionResponse`（`response: {result}`）；tools→`functionDeclarations`/`parametersJsonSchema`，tool_choice→`functionCallingConfig`；`parallel_tool_calls: false`、`user`、图片、strict 工具 422。响应：单候选，文本 concat，`functionCall` 转 tool_calls（无 id 时 `call_<n>`），`STOP` 且有函数调用时为 `tool_calls`，安全类原因为 `content_filter`，prompt 被拦截时输出空内容的 `content_filter`；`thought` 部分 502 unsupported。用量与 legacy 相同：input = prompt + toolUsePrompt - cached，output = candidates + thoughts，reasoning = thoughts。SSE 无终止事件：带 `finishReason` 的帧携带最后增量与 finish 作为保留终态，usage 块与 `[DONE]` 以 `extra` 追加；其后数据或 EOF 前无 finish 均失败。
- **j5 Bedrock**：`gateway.bedrock-anthropic-1.0.0` 与 `gateway.anthropic-messages-1.1.0` 共用 `packages/adapters/anthropic-messages/messages.ts`（目标 `anthropic`/`bedrock`；Anthropic 包字节因源码拆分变化而升版，行为不变）。Bedrock 目标：请求体去掉 `model`/`stream` 并以 `anthropic_version: "bedrock-2023-05-31"` 开头，路径 `/model/<encodeURIComponent(upstream_model)>/invoke`（流式 `invoke-with-response-stream`，带 `x-amzn-bedrock-accept: application/json`），auth `{type: "aws-sigv4", service: "bedrock"}`；manifest `stream_codec: "aws-eventstream"`，宿主 `packages/plugin-host/src/aws-eventstream.ts` 按 E7 解码后复用同一 Anthropic SSE 帧逻辑。`packages/runtime` 的 SigV4 拆为 `awsSigningKey`/`awsAmzDate`/`signAwsRequest`，legacy `signBedrock` 改为调用它们（既有固定签名用例不变）；Core 派生密钥，Gateway `authorize` 在最终 URL/头/体上签名。解码器拒绝内部 JSON 含原始 CR/LF（Bedrock 输出为紧凑 JSON），以免破坏 SSE 帧边界。`scripts/build-plugins.ts` 改为按 esbuild metafile 记录全部被打包的 `packages/` 源文件哈希。

## 5. 已知差异与未完成

- chat 响应 `created` 为 0：guest 无可信时钟，legacy 使用当前时间。
- data URI 图片（需拆分 media type/base64）在 Anthropic 插件中 422，legacy 支持；需要新的通用字符串切分能力，未在 j2 实现。
- 单轮 inspection 展开 ≤4096 个事实且事实 JSON ≤256KiB，超长对话会以宿主预算错误失败，而不是降级。
- Gemini 插件不支持图片（data URI 需切分，`gs://` 需 mime），legacy 支持。
- 未定位的偶发失败：j6b-2 期间两次完整门禁各有 1 例“成功请求之后紧接的请求返回 503”（`gateway-plugin-lifecycle` 回滚后重绑、`gateway-lifecycle` 熔断探测关闭后），单独与 2 路并行共约 36 次及一次带 5xx 日志的完整集成运行均未复现，未取得错误码；最终提交前完整门禁通过。保留为待查项，不宣称已修复。
- j6a 同协议与 j6b 跨协议入站已完成（跨协议以 chat 为中间格式，仅转换到声明 chat 的插件；插件之间的非 chat 直连转换如 Messages→Gemini 原生不做）；j7a、j7b 已完成，j7 验收（自审与 legacy 退役条件）尚未完成。
