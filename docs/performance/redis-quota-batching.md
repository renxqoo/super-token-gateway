# Redis 配额租约合批

Core 按独立的 Redis 配额端点合批提交租约操作。每个端点空闲时可立即提交单笔，积到至少两笔时收集 4 毫秒。单批最多 512 项、至多一个批次在途，等候队列最多 2048 项。JSON、SSE、重试和回收使用同一套租约和计数。Redis 按原规则逐项执行，单笔限额拒绝不影响同批其他操作。续租去重历史保存在 Redis，租约证明响应省去这段历史。

队列满、超时或关闭时返回配额不可用。连接就绪后和脚本缓存未命中的回退发送前剔除过期操作。已发送且结果未知的操作由租约幂等和回收机制处理。发权依赖 PostgreSQL 的持久记录和有效的 Redis 租约证明。

合批实现曾在本机工作树用 `appendfsync=always`、每秒 3210 笔固定到达、30 秒窗口与 512 个在途名额比对逐项提交。每笔包含项目、密钥和渠道三个作用域的申请、绑定和释放。Bun 1.4.4 下窗口内完成数从每秒 410.20 提升至 3203.37。Bun 1.4.5 复测为 3205.13。两次合批均完成全部 96,300 笔，零失败和零丢弃。公开 API 的吞吐按有效 HTTP、精确结算与外部 ACK 三项交集单独验收。
