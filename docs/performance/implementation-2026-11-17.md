## 3. 发送身份与资金保持

新增append-only迁移2026111705、私有owner审批、V2 projection/prep/authorization plan；Gateway根据私有验签身份、精确本地资产和PG上下文能力同时选择。PG独立核当前批准，BEGIN保持原permit构建，不在已准入后降级执行器。发布者插件及资源GET/poller继续Wasm。

实际公钥指纹与统一dispose的两项独审发现已红绿修复。新10例真实边界验证91断言通过，含运行中Gateway在线切Worker/CLI撤销回Wasm、未审批摘要无资金写入、旧context不扩大、BEGIN撤销、实际角色权限、TRUNCATE交错、NULL包当前验证、等锁过期回滚和累计审批期限。旧V1许可由旧29项schema/SQL和真实Redis租约生成，UNKNOWN由签证与合法状态转换明确播种；升级后HTTP query/abort和后续签证结算通过，客户总200、供应已支出22、reserve=0，27个断言包含在前述验证内。

## 4. S3c锁竞争回归

S3b失败轮PG日志中出现core_quota_v1锁冲突。该函数的单条隐式事务会完整回滚，但store.quota原先没有已知BUSY重试，BEGIN将错误归为未知结果。自有100ms permit锁已确定性复现：解锁前请求提前失败，0通过/1失败；这证明该类故障，不足以把S3b全部10个503都归因于它。

修复只对55P03/P0503重发相同PG参数，不重发Redis ADOPT/RENEW，不重试08006等未知提交错误。单调上限1秒且不超过caller deadline，迟到timer不得再次写库；BEGIN仍按原proofDeadline实时扣减。permit和租约行两个真实回归2通过8断言，阻塞期间无部分ACTIVE，释放后只记一个BEGIN回执。quota/context单元6通过9断言，独立只读审查无有效问题。修复后40档连续两轮通过，但不能从一类已复现故障的消失认定此前全部503都已确定根因。

40档两轮含预热请求2533/2529，所有计量/收费/供应成本/外部ACK一致；窗口后244/221ms排空。50档所有3127个含预热请求最终正确完成，窗口完整交集2992，排空793ms，仍失败。60档所有3727个含预热请求最终正确完成，窗口内完整完成3336（55.6RPS），窗口后2849ms排空；即使HTTP P99低于门槛、120秒内可排空，完整窗口吞吐仍失败。当前连续两轮稳定下界为40RPS，不从失败轮推算50或60已稳定。
