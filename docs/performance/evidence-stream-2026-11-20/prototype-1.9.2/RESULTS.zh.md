# 本地合成签发 1.9.2 三宿主 SSE

固定到达快流 3010/s 持续 60 秒，共计划发送 180600 笔请求。发生器丢弃 3796 笔，实际进入的 176804 笔全量单发、完成 HTTP SSE、同步主备资金和逐笔签名见证，并获 353608 个外部 ACK。窗口内完成 176478，合计 2941.30/s，端到端 P99 832.704ms，首内容 P99 744.096ms。钱包与供应商单元零核对异常。门禁未达，未重复该配置。orderFailures 的 3796 包含未发出的全部请求。已发请求的业务时序完整。报告以固定到达日程为延迟起点，完成时刻覆盖 HTTP 和全部 ACK。

与此前 1.9.1 三宿主实验的 2282.42/s、P99 1038.033ms 相比，1.9.2 流处理每次成功调用的底层 worker 消息数从 23 降至 14，单机网关进程 CPU 按成功请求折算从 3.211ms 降至 2.282ms。两轮同时包含适配器和宿主差异。源自合成发行的实验已与生产安装/管理审批区分，母区正式入口容量应另行报告。

4/s 三秒延迟输入的 12 笔全部在首内容交付前见证 PARTIAL，各自首内容至少比上游终止早 392ms。2/s 两秒、每笔四十段的多段流共四笔，实际执行八次 stream_drain。所有运行的独立进程、临时目录、端口、计时器、活跃请求退出时均清零。

同版发生器连接并发对照保持 2048 在途、三宿主、384 执行预算。仅增加参数白名单对 512 的支持。两个 10 秒样本均 30100/30100 单发、收齐资金与外部 ACK，零 shed。默认入口并发峰值 256，窗内 2869.1/s，P99 520.824ms。将连接上限调至 512，入口并发峰值升至 512，窗内 2863.2/s，P99 585.900ms。未再测此配置的 60 秒窗口。先前 60 秒的丢弃集中在第十秒至第三十秒，十秒校准不能判断后段丢弃是否会变化。

原始入口、客户端、上游、签名阶段、资金/备库核对及外部 ACK 的 TSV 和独立重算脚本均附在压缩包内。实验使用回环 HTTP 公开原型与同步 PostgreSQL 17，本地签发包和运行期签名公钥不代表已获生产审批。实验范围见各自源码包 README。
