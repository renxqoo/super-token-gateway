# 隔离渐进 Chat SSE 联合测量

同机、单一回环公开 HTTP 试验入口，60 秒以固定 3010 次/秒提供请求。联合完成按同一 request、attempt、逐份 evidence 的客户端合法 SSE、备库资金见证、一次上游接收、独立消费者 ACK 交集计算。每个 60 秒窗口均有 180600 次 offer。

| 单宿主 |  77625 |                 77625 |           75577 | 1259.617 |      1678.469 |    1724.126 |         102975 |                  155250 |
| 三宿主 | 139023 |                139006 |          136945 | 2282.417 |       981.003 |    1038.033 |          41577 |                  278012 |

三宿主的联合窗内吞吐较单宿主提高 81.2%。在三宿主窗口内，有 17 笔成功预留资金后遇到上游 ECONNRESET，未进入 mock 的接收记录，未重发。17 个钱包、8 个供应商单元有未释放的测试预留，异常门禁失败。单宿主 60 秒的实收全部结清。两轮均未通过每秒 3000 和全量无缺失门槛，每个 P99 使用有完整三方交集的样本。缺失及失败次数独立列出。

同一版、相同主备及入场条件的 10 秒短对照为 1265.6/s 与 2154.1/s。未分区对照的 14747 次实收中有 31 笔真实发行宿主 JSON_MEMORY_BUDGET 错误，三宿主短对照实收 23571 笔全齐。同一轮的语义验证显示，三宿主的每笔普通短流有 2 次 prepare worker 消息以及 23 次流 worker 消息。三宿主将整笔请求分给独立宿主，公开入口和资金写者共享。背压仍在单请求 pull 和全局 384 个执行位置上生效。

低档延迟上游的 12 条请求均有首内容与 PARTIAL 用量同时上报。单 / 三宿主依次至少提前 393 / 394 ms 将首个完整内容增量送达客户端。每条均先持久化首份 PARTIAL 签名并在指定同步备库核实，才返回这部分内容，每次运行共 36 份签名与 ACK。4 条独立的 40 段突发文本流触发 24 次 stream_drain，4 条均通过全量文本、结束标记、账务和双事件 ACK 检查。

单宿主 60 秒内，实收样本的客户端调用 fetch 至公开入口实际接收中位耗时 1409 ms，P99 为 1493 ms。单次上游真实接收到上游完成的中位耗时为 0 ms，P99 为 1 ms。其后到网关完成流消费的中位耗时为 150 ms，P99 为 187 ms。单宿主入口和内置 worker 合计约 159.12 CPU 秒，按实收计算为 2.05 毫秒/笔。本机 CPU 采样将同进程 worker 线程纳入入口 PID。三宿主该项为 446.29 CPU 秒，约 3.21 毫秒/实收。分区提高并行度，也增加跨宿主消息和总 CPU 成本。

短流的 mock 在一个上游块内给出所有内容，短流高档本身不能证明提前首出；延迟和突发两个夹具分别检查逐块交付和 drain。试验入口省略正式 Gateway 的用户认证、mTLS、Redis 分布式额度、生产 AOF、完整取消退款、故障恢复等路径。仓库的正式入口需独立验收。

source-a 是首轮、paced-b 和 burst-a 使用的源代码。source-b 包含可切换 0 / 3 个独立宿主的同版程序，对应 control10、pool10、pool-paced-b 和 pool-3010-a。源包内的 README 有依赖和命令。解开原始记录后，可用同目录 recompute.py 和 profile.py 传入 evidence 下的运行前缀重算结果。原始运行 JSON 中记录发行包、策略、公钥、工具链以及各 TSV 的 SHA-256。每轮都保存清理报告。
