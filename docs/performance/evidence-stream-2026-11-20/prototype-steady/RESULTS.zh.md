# 1.9.2 三宿主 SSE 连续三分钟

同一台机器连续按 3010/s 固定到达，共 541800 个不同请求 ID。三个 60 秒子窗口共用真实 PG 主备、同一路由、三宿主和同一临时签名公钥，既不清库也不重启。资金、增量签名与外部 ACK 使用单次终态 SQL 版本。依计划到达时间归组，完成需要 HTTP 有效、上游单发、资金及所有签名和外部 ACK 同一身份齐全。早期请求拖入后窗的完成单列。最后一个窗口的有效速率以夹具实际排空计时。正式 Gateway 的生产 mTLS 和管理审批等不在此单机实验内。

| 计划到达时段 |   实发 | 发生器丢弃 | 最终联合完成 | 自身窗内完成 | 上窗遗留完成 | 窗内联合 RPS | 含本组尾批 RPS |  完整 P99 |
| ------------ | -----: | ---------: | -----------: | -----------: | -----------: | -----------: | -------------: | --------: |
| 0–60 秒暖机  | 178346 |       2254 |       178346 |       178049 |            0 |    2967.4833 |      2967.8332 | 813.266ms |
| 60–120 秒    | 180600 |          0 |       180600 |       179750 |          297 |    2995.8333 |      2998.5057 | 356.136ms |

两个暖窗均未达严格门槛。第一窗全部请求闭环、逐笔收齐 361200 个 ACK，跨窗 850 笔，自身全部收齐耗时 60.230 秒。第二窗的 180598 笔有上游接收记录，180592 笔对账并收齐 361184 个 ACK，另有 8 个 HTTP 500。其边界有 1257 笔之后成功，8 笔最终未闭环。最后一笔联合完成晚于窗口末 353ms，实际结束排空晚 570ms。两暖窗都没有发生器丢弃。全程先前 60 秒冷启动门槛的失败结论保持有效。

全程无二次上游发送。10 条保留错误样本都是上游 fetch 的 ECONNRESET，上报可能重复。8 个未闭环身份中，6 个供应商模拟服务接收到请求，2 个没有上游接收记录；共有 8 钱包、6 个供应商单元余额或预留核对异常。该实验只模型化成功资金链路，其异常资金状态计入失败。程序退出时数据库、子进程、目录、端口和计时器均清零。按所有身份独立重算确认 539538 笔最终闭环，全程 1079076 份签名证据获外部 ACK。

## 离线核对

交付目录的 `SHA256SUMS` 给出每个 64 MiB 或更小分卷及源码包摘要。`REASSEMBLED.sha256` 给出按序拼接后的完整压缩流摘要。源包与数据包分别解压后，cohorts.py 会从六份原始 TSV 重新核对身份、时序、窗口、外部确认和资金匹配。此失败样本的严格核对退出码为 1，结果保存在标准输出中。

```sh
shasum -a 256 -c SHA256SUMS
cat sse-warm-180.tar.gz.part* | shasum -a 256
cat REASSEMBLED.sha256
tar -xzf sse-source-192-three-minutes.tar.gz
cat sse-warm-180.tar.gz.part* | tar -xzf -
python3 -B source/cohorts.py evidence/warm-180 60 --require-warm
```
